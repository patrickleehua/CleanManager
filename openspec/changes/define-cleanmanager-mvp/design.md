# Design

## Context

动机见 [proposal](proposal.md)。当前是 greenfield 项目：已有 `docs/`、2 份 Schema、合成样例、Python 文档验证器和 REA 证据；没有 Rust workspace、产品 CLI、桌面或产品测试。OpenSpec 使用本地 spec-driven，main specs 为空。本变更的 9 份首版 delta specs 与 1 份可选 AI 扩展 spec 是拟实现行为，并不表示已通过平台验收。

研究约束来自 [核心架构](../../../docs/core-architecture.md)、[Windows](../../../docs/platforms/windows.md)、[macOS](../../../docs/platforms/macos.md)、[协议](../../../docs/cli-protocol.md) 和 [验证计划](../../../docs/verification-plan.md)。WizTree 证据覆盖 portable 清单/PE 资源，原生调用链仍未知；disk-cleaner 只有合成分类探针。自研方案不依赖补齐竞品反编译。

用户直接提出的是：Windows/macOS、Rust 优先、Mole 式人工管理、WizTree 式空间定位、独立 Agent CLI/Skill。以下首版边界与参数是本变更的设计选择：Tauri 桌面、只读应用清单、少量验证规则、15 分钟计划有效期、无默认常驻服务、卸载/TUI/MCP 后续扩展。它们不应被写成用户已经明确指定的所有细节。

## Goals / Non-Goals

**Goals:**

- 一个核心服务人工、CLI 与 Agent，所有写入通过相同计划、授权、核验和日志。
- 先建立真实双平台只读基线，确认字段与范围，再开放验证过的清理能力。
- 每项可发布能力有明确平台/权限/文件系统边界、对应 spec 和测试证据。
- 保持核心与平台/界面依赖分离，允许分别更新显示和扫描实现而保持外部语义。

**Non-Goals:**

- 不在首版建立动态执行脚本插件、默认系统 daemon 或任意路径删除服务。
- 不要求 Windows/macOS 使用相同底层机制，也不要求界面全部用 Rust。
- 不在此变更中实现原始在线 APFS 解析、原始 MFT 产品后端、增量索引、自动卸载或硬件优化。
- 不以本工具规则隔离拥有同 UID 任意 shell 能力的 Agent；需要该能力须另设计 OS 隔离。

## Decisions

### D1. Rust library、独立 CLI 与 Tauri 桌面

拟建 `cm-core`（领域服务与状态机）、`cm-platform`（条件编译的系统访问）、`cm-cli`（参数/格式/人机入口），桌面 Rust 宿主直接调用核心，TypeScript 负责呈现。先用静态后端/规则注册，不为每个模块制造运行时插件。

依据：Rust 适合类型化领域接口和原生访问；同一 library 避免 GUI/CLI 分别实现删除逻辑。Tauri 满足 treemap、表格和桌面交互需求，代价是 WebView2/WKWebView 分别验证。替代方案是纯 Rust GUI、各平台原生 GUI 或 Electron；当前优先复用界面技能，把工程重点放在扫描与执行正确性。原生 shim 可用于必须由系统框架处理的服务，不形成另一套规则内核。

### D2. 两个平台各有原生后端与独立基线

Windows 先实现限定目录的批量信息枚举 `win.directory`，再在明确卷级范围/权限下验证 `win.ntfs_enum`：枚举身份和名字后补齐大小/链接资料，端到端测量含补查、对账和索引提交。macOS 实现 `mac.posix` 基线与 `mac.bulk` 批量属性扫描。优化不改变字段语义；条件不满足则退回限定范围扫描或报告不可用。

初始每卷 2 个目录 worker、最多 8 个补查并发、8,192 条队列记录和 64 MiB 队列预算，均为可调整起点。线程/批次有界，阻塞 I/O 与异步 UI 调度分开，不为每个文件产生无界任务。

选择自研后端而非外部 WizTree 执行依赖，可保持跨平台发布和字段控制。原始 MFT 与在线 APFS 解析暂不采用；是否投入额外解析由基准和后续独立变更决定。云盘接口未验证时跳过边界，补查也遵守防物化策略。仅“metadata-only”名称不作保证。

### D3. 统一实体、原始路径和空间观察

核心区分 FileObject 与 DirectoryEntry；文件实体以卷身份、带类型的原生文件 ID 和可得代次标识关联，目录项保存父实体和原始名。弱身份只用于有限分析，不升级为特权执行证据。盘符/显示路径不作为卷身份。

Windows 原始路径保存 UTF-16LE Base64，macOS 保存原始字节 Base64；显示值仅呈现。不同卷的大小写/Unicode 规则由平台访问层保持。字节值在 Rust 为 u64；JSON 为十进制字符串；SQLite 索引可用固定 8 字节大端值进行精确大小排序，汇总在核心做检查加法，不用 SQLite 有符号整数强制装下所有 u64 或按十进制文本词典序排序。

逻辑/分配/回收估计/卷空闲四种观察分开，带来源和有效性。未知分配或共享块不能变成 0；全实体与目录展示采用分别声明的归属口径。替代方案是只存全路径与一个 size：实现更简单，但无法可靠处理硬链接、改名、无损路径和共享空间，故不采用。

### D4. 版本化 SQLite 索引与独立审计恢复责任

扫描批量写 staging revision，发布后查询绑定 scan_id/revision。取消或有限失败也可发布带 partial_scope 的确认部分。游标绑定 revision、范围、排序、过滤与最后稳定键；可用索引覆盖父项、大小和身份，按需构造全路径，不把全盘数组传入 WebView/模型。

扫描索引与操作/恢复记录在逻辑及故障恢复策略上分离；可再生索引允许重建，audit/intents/隔离清单不得随重建消失。写动作使用跨进程范围锁及事务登记。SQLite 本地事务不被描述为文件系统批次事务。

任务记录包含宿主身份/生命周期证据和最后状态。首版任务由发起 CLI 或 GUI 宿主进程承载；另一个进程可查状态或记录取消请求。宿主退出时扫描变成中断/不完整，未确认写动作进入核对。以后若需退出后继续任务，再新增受限任务服务，不假装当前已有 daemon。

### D5. 有证据的声明式规则和有限候选

规则声明平台、根解析器、应用身份、匹配/排除、生命周期、影响、允许模式及测试证据。首版仅发布少量对应应用/系统版本真机验证过的缓存/过期临时文件规则；具体列表由同一个规则验收任务登记，实验规则不自动进入启用集。

保护项优先；部分扫描按规则需要的证据范围判断；跨规则去重。父项含被保护/未知后代时细分叶子或拒绝整组。替代方案是复制路径子串匹配或让 LLM 判断安全；既有探针说明这不足以证明归属/可再生，故只借鉴参考项目的工作流。

### D6. 固定计划和版本化元数据前置指纹

采用现有草案 `CM-C14N-v1`：规范化完整 PlanBody，ASCII 字段名排序，UTF-8 紧凑编码、固定数组顺序、不允许浮点/重复键/未知字段，SHA-256。所有输入字符串是可序列化 Unicode；原生异常路径单元保存在 Base64，不损失原始路径。动作按 action_id 排序。同一 body 有同一摘要；独立新建时生成 ID/时间不同，测试比较动作语义或固定这些生成输入。

元数据前置条件采用内部 `CM-OBS-v1` 有界记录：scope 根身份、卷/实体/父链身份、原始路径、类型、logical/allocated 大小、可得代次、原生 mtime/change 标记、链接/reparse/云属性，以及每字段来源/有效性；不可得字段显式 null。时间标记携带原生单位/表示，不用显示时间反推。与计划同样规范化后生成 observed_fingerprint_sha256；不读内容哈希。

完整前置记录保存在权威观察存储，hash 用于绑定，不能从 hash 推导缺失属性。只按存储 plan_id 应用；首版不接收外部任意计划导入为执行授权。指纹只是 stale 检测之一，不替代现场句柄/父项核验或原子身份约束。

每份清理计划 mode 为 quarantine、trash 或 delete，默认 TTL 900 秒；修改内容产生新计划。恢复/清空使用独立类型的计划（契约 `recovery/v1`），包含隔离对象、已确认源身份、原目标/指定目标及冲突条件，与清理计划共享授权/日志服务，不把 restore 硬塞进现有三种 mode。

### D7. 人工授权、有限策略与跨进程额度

用户可在 GUI 或受控终端审阅存储计划。授权凭据独立绑定主体/摘要/模式/范围/到期/撤销状态。终端 TTY 只解决交互呈现；它不证明真人，也不防止同 UID 完整进程控制。普通用户动作遵循此威胁边界；特权 helper 必须有独立可信 caller/凭据核验，不只信用户可写数据库。

预授权默认关闭。初始策略模板参考已有产品设计：精确规则版本/根/模式、30 天有效、单次不超过 1 GiB 且 1,000 项、滚动 24 小时不超过 2 GiB 且 2,000 项。数值可由用户在支持范围内配置，未知规模/归属/生命周期不自动命中。跨进程事务保留额度；unknown 副作用占用额度直到核对，已产生动作不回退额度，拆批累计也受约束。范围内执行不逐次弹窗。

替代方案是 `--yes` 授权或每次强制批准：前者丢失范围绑定，后者无法满足已有有限授权的重复工作流。`--non-interactive` 仅禁止提示，缺授权返回 needs_approval。

### D8. 保守的原生执行与核对状态机

按固定叶子列表执行 durable intent → 现场复核 → 原生动作 → durable result。检查卷替换、ID 重用、父链/保护/模式、云边界、权限及授权时限；新文件不加入旧计划。锁键覆盖范围/实体，不只覆盖 plan_id；不同键重复应用同一计划仍返回同一 Operation。

Windows 验证句柄动作及原生回收站的真实约束；macOS 的 parent fd + check 后 unlink/rename 仍有最后名称竞态。按 [平台设计](../../../docs/platforms/macos.md) 的能力门槛验证允许的命名空间/动作；无法满足严格要求的能力关闭。尤其不让高权限 helper 对低权限可换名的任意目录执行递归删除。

保护更新可收紧执行范围；授权撤销/计划过期停止新的动作，不撤回已发生的 OS 调用。结果区分成功/跳过/失败/未开始/未知，未知进入 reconciliation_required。取消/崩溃不自动回滚或重试；只能核对后推进。

同 UID 恶意进程属于已说明的隔离边界，正常并发文件变化仍需实测。若真实平台证明首版目标范围无法实现对应写动作，不能以“正确拒绝”冒充清理闭环；保留只读版本，并通过新的规划决策解决缺口后才声称完整 MVP 达成。

### D9. 恢复和收益报告使用独立事实

同卷隔离用私有位置及唯一名称，保存原父身份/名字、目标身份、元数据与恢复限制。首次移入隔离仍须满足原生竞态要求，私有目录不解决首步竞态。跨卷备份后删除暂不实现。回收站失败不降级删除；产品内不可恢复时显示系统指引。

恢复先重新计划；原位置有新对象则默认冲突不覆盖。到期提醒默认 30 天，不自动清空；清空另建带授权的 purge 计划。报告保存 processed 量及卷空闲前后观察，差值允许为负，不把同卷移动量等同释放量。

### D10. 补全首版 CLI 草案而不暗改已发布协议

现有 v1 没有用户发布，后续实现先在同一草案版本补齐严格定义和正反例，再冻结发布契约；冻结后新增不兼容结构需版本协商。二进制、数据库、规则与协议版本分开。

| 命令组 | 决定采用的首版接口 | 响应边界 |
| --- | --- | --- |
| 能力与扫描 | capabilities、scan --root、scan show、scan cancel | 完成结果与 scan_status、取消回执是不同记录，不能把 running 放进 scan_result 终态枚举 |
| 目录与分析 | entries list、analyze、candidates list | 分页包装含 scope/revision/next_cursor；分析结果提供 candidate_set_id，不靠解析文字取得 ID |
| 计划 | plan create/show/apply；plan review ID 供人工终端审阅 | 机器接口不提供无交互自批；human review 读取存储 body，不接受客户传入 approved 标记 |
| 执行 | operations show/cancel | operation_status 与终态 report 分开；去重键/摘要冲突返回 conflict |
| 隔离 | recovery list/show、recovery plan create | 新建 restore/purge 的 recovery_plan；共同的 plan review/apply 按权威计划类型调度，不凭任意 mode 字符串切换 |

运行态包装携带 task/operation ID、状态、时间、已知统计和最近错误；终态引用现有 terminal record。取消回执只表示请求已接收，不声称 I/O 已停止。所有请求/响应、恢复类型、元数据指纹和键行为在任务 2 的契约步骤落为 Schema/样例，然后才实现写能力。

JSON stdout 一个终态，JSONL 有序 progress 加一个终态，日志走 stderr；非 TTY 默认 JSON，格式冲突报错。页大小 1–500、默认 50。退出码沿用既有分类；**reconciliation_required 返回 operation_report + 8**，禁止自动重试，不返回一般 success。

`--timeout` 是等待预算：超时请求取消本次宿主工作，写入原因和可查询 ID，在安全边界退出；不承诺不可取消 OS 调用能准时返回，也不承诺工作已回滚或无人托管仍在后台运行。timeout 结果进入系统失败分类 8；显式用户取消为 130。已经确认的逐项结果仍保留。

精简 Agent Skill 提前纳入首版，内容仅为能力→摘要/分页→解释→计划→授权处理→执行→报告及错误分支；实际 Skill 包在 apply 时按相应创建工作流生成。TUI/MCP 仍后续，避免首版维护多份领域逻辑。

### D11. 桌面查询、可访问性与只读应用清单

桌面采用 P01–P10 旅程，但通过核心查询分页/按层 treemap。UI 不执行路径删除，订阅使用有界窗口并丢弃过期查询结果；选择绑定 entry_id/revision，隐藏选择可审阅，刷新不自动选中新文件。图表面积口径固定、未知空间单独说明；表格为完整等价入口。

Win/Mac 原生信息来源建立独立安装实例清单和目录关联。签名/bundle ID/卸载注册信息是证据而非删除许可；共享容器与未知残留保留。首版不调用外部卸载器或统一开关第三方登录项。

读屏/键盘/缩放在 WebView2/WKWebView 真机验证，危险状态有文字而非仅颜色。导航不取消工作；宿主退出行为与 CLI 一致，重启先呈现中断/核对。视觉可借鉴简洁维护面板与 treemap，不复制竞品资产。

### D12. 能力门禁、本地隐私与分发

全盘树、文件内容和凭据不默认上传。索引/恢复记录保留本机，诊断有明确范围和脱敏选择；对外 Agent 后续发送数据由其运行环境决定。基础 CLI 可独立发布，GUI/CLI 均需对应平台签名/公证、架构和安装验证，更新器签名与平台签名分别验证。

初始优先 Windows 11 x64、真实 Apple Silicon Mac；最低 build/macOS 版本和依赖版本在只读 G0 决策包冻结。ARM64 Windows/Intel Mac 是额外实机矩阵，不以仿真或交叉编译代替。签名身份、更新和 helper 兼容联动测试，不通过关闭安全保护完成验收。

### D13. 可选 AI 诊断解释对象，不替代规则与授权

用户补充的亮点是解决“看不懂文件、怕删错”的决策问题。AI 诊断作为首版之外的可选扩展，覆盖清理候选、未知大文件/目录及应用关联数据。现有“AI 与开发者”页面管理缓存/会话/模型空间；新增“AI 诊断”是上下文入口与独立工作台，两者不混称。没有模型配置时仍能正常扫描、规则解释、计划与恢复。

诊断绑定对象 ID、scan_id/revision、观察指纹与时刻，核心生成有界证据包；默认仅包含脱敏位置、类型、逻辑/分配大小、归属/规则/保护/共享与覆盖资料，不遍历整盘、不读内容、不物化云占位。用户发起后先预览目的地和实际字段；额外路径、子项样本或片段逐项选择，再次发送需新的范围确认。文件名、用户补充与模型输出始终作为不可信数据。

返回版本化结构：用途解释、recommendation（reviewable / needs_context / keep / unsupported）、依据引用、假设/缺口、删除后果、重建与离线成本、替代办法、少量关键问题和允许的下一步。已观察事实、规则资料、用户陈述和模型推测分开；不输出“93% 安全”式许可，也不能伪造本机占用/备份/依赖检测或独占可回收字节。原始回答无效时不提取其中删除指令，保留本地事实并显示错误。

用户自配 API（可配置兼容端点/模型，包括经验证的本地端点）或已有 CLI；“COI”暂按语音输入中的 CLI 理解。连接测试仅发无文件资料的能力探针。API 凭据放系统凭据存储，不进入前端、索引、诊断历史或日志。CLI 适配器使用用户选择的可执行文件与结构化参数/stdin，禁止 shell 拼接，限定输出、时间和工作目录；只支持可以验证无文件访问/写入/工具调用的诊断模式，无法约束的 CLI 标记不支持。账号额度/费用由供应方规则决定，不宣称已有订阅必然可复用。

AI 给出建议后，核心独立决定行动入口：已经有有效候选与能力的对象可生成原有不可变计划，照常审阅授权和现场核验。未知安装包可展示验证来源、安装状态及重新获取方式；个人视频可询问备份/项目引用，选择保留或定位；模型/共享数据可指向经适配的应用管理入口。用户说“已备份”不会变成已验证事实或取消保护。本扩展不新增任意路径删除，也不把未知文件自动转换为规则候选；若未来需要精确手选普通文件的回收站流程，另建独立能力规格与验收，而非由模型输出暗中开启。

GUI 使用选中对象摘要 + 诊断正文 + 右侧依据/信息范围，桌面与窄窗口堆叠同一组件。追问只绑定当前对象，范围增加回到预览；导航不隐式取消，明确取消/超时/断连/CLI 不可约束/结构无效/观察过期。结果带 provider/model/template 版本与时刻，旧回答仍可读但过期时关闭行动。诊断历史默认仅本机会话保留，可主动保存/移除；输出给外部 Agent 属于新的披露选择，不自动把配置诊断的提供方与 Agent 运行环境合并。详细旅程与原型映射见 [AI 诊断设计](../../../docs/ai-cleanup-diagnostics.md)。

## Risks / Trade-offs

- [Mac 设备与权限证据缺失] → 独立登记设备/运行环境任务；未测能力保持 unverified，G0 不把 Windows 结果复制过去。
- [原生快速路径补查成本可能抵消收益] → 用同范围/字段的目录基线比较完整索引完成时间；保留遍历路径，不预写秒扫文案。
- [名称竞态和 helper 权限边界限制可清理范围] → 实测可发布动作，拒绝无法满足约束的能力；闭环不足时不宣布 MVP 完成。
- [云 metadata 查询也可能触发下载] → 固定受控 I/O 策略、按 provider 验证；无法归因或保证时跳过。
- [审计写入与 OS 动作不是同一事务] → durable intent/result 与 unknown 核对，故障注入覆盖每个窗口，不盲目重试。
- [严格协议与不断补齐草案存在冲突] → 发布前集中冻结，冻结后协商版本；新结构有独立类型和样例。
- [完整首版提案包含多个模块] → 用 G0/G1/G2 和小任务组织，apply 先执行只读部分；尚未通过前提时不跨门禁开放写/发布。
- [用户配置可被同 UID 进程修改] → 说明真实威胁边界；特权能力验证独立凭据，不把策略文件宣称为安全沙箱。
- [模型幻觉、诱导文本、内容外发与 CLI 工具权限] → 证据分层、实际载荷预览、核心动作门禁与可验证的诊断适配；拒绝不受约束的 CLI，不让 AI 自动生成执行脚本。

## Migration Plan

1. **规划到实现：**此 propose 只落规划文件。收到新的 apply 请求后，先完成契约和受控夹具，再创建只读 Rust 原型。
2. **G0 只读：**真实双平台跑字段、范围、权限、云边界、取消和基准；冻结已验证平台矩阵、后端与性能预算。缺证据时继续相关实验，其他不依赖项可推进。
3. **G1 核心/CLI：**候选→固定计划→授权→执行→核对→恢复闭环，只发布已验证规则和动作。只读入口可提前联调，写能力不跨过 G0/专项证据。
4. **G2 桌面/发布：**增加 P01–P10、应用清单、可访问性和大数据测试，完成独立 CLI/GUI 安装、签名、更新、数据迁移及用户旅程验收。
5. **故障/回退：**索引可重建；审计/恢复迁移先保持可读或备份受控副本。更新前停接新写任务，保留未确认动作。迁移失败回退程序时先检查数据兼容，不覆盖新格式，不重放旧计划。
6. **后续：**增量索引、卸载/维护、TUI/MCP、外部 CSV 和更多架构另建能力变更，不把本次首版任务永久挂在所有未来功能之上。
7. **AI 扩展：**任务 15 独立实施/验收，复用已经成立的只读证据与计划服务；可在核心开发期间完成 UI/契约原型，但不进入 G0/G1/G2 的强制发布门槛。无 AI 配置的首版仍应完整可用。

## Open Questions

以下属于不改变本次行为合同的校准项，由对应任务产生证据；不得跳过任务后把它们写成已实现：

- 实测后的 worker/batch/队列参数和数据集上的性能预算；参数改变不改变范围/字段/授权语义。
- 具体 Rust/Tauri/SQLite 与 SDK 版本、支持矩阵中的最低 OS build，以及签名证书配置；依赖/平台验收步骤已固定。
- 第一批满足规则证据要求的实际应用版本与缓存清单；验证标准和未通过处理已经固定，未确定前不启用生产规则。
- 可保留的 ACL/ADS/xattr/稀疏元数据具体覆盖；逐项恢复能力以测试结果说明，不改变冲突/授权要求。
