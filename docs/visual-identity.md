# 视觉标识、信息架构与资源清单

最近更新：2026-10-22（P3–P5：磁盘、清理、计划审阅、执行结果与其余页面的层级与缩放）。对应 OpenSpec `add-mole-parity-suite` 任务 16.1–16.5 与 GUI-08..14。实现位于 `apps/desktop/src`：令牌在 `styles.css`，图标与标志在 `lib/dom.ts`，导航与快捷键在 `lib/nav.ts`，平台惯用语在 `lib/platform.ts`，统一选择/审阅/结果组件在 `views/kit.ts`，状态横幅、问题行、路径等共享展示组件在 `views/ui/`，代码 → 中文表在 `lib/codes.ts`，磁盘 / 计划 / 执行结果的状态模型在 `lib/diskModel.ts`、`lib/planModel.ts`、`lib/operationModel.ts`（各有单元测试）。

## 设计方向

CleanManager 是一个“先看后删”的磁盘与系统整理工具，主要用户在 Windows 上整理自己的文件，同时需要随时知道哪些东西不会被动。视觉延续 suite-v3 原型已建立的基调：

- **颜色**：几乎中性的灰色纸面（`--bg #f5f6f5`）、白色面板、深松绿强调色（`--accent #2e7a62`，唯一有饱和度的品牌色），警告用陶土棕（`--warn #8a6327`），危险用砖红（`--danger #a84d3e`）。深色主题是同一套色相的低亮度版本，不是反相。
- **字体**：使用操作系统自带字体（Windows：Segoe UI Variable / Microsoft YaHei UI；macOS：PingFang SC），不打包任何字体文件；数字使用等宽数字（`tabular-nums`）。
- **唯一的醒目元素**：左侧“工具栏”——原创标志加五个工具图标，当前工具以松绿刻痕和面板底色标出。页面本身保持安静：同一种页头、同一种工作区 + 右侧决定栏、同一种底部选择栏。
- **状态从不只靠颜色**：每个状态都有形状 + 文字（实心圆=低风险、半圆=需审阅、斜杠方框=已阻止；结果条的成功/跳过/失败/未知各有形状）。

### 信息分层规则（P0）

- **一页一个主信息**：页面顶部只有一个主元素（概览上是状态横幅：形状 + 含状态词的标题 + 一句话 + 下一步）。其余内容按“主 → 次 → 细节”往下排。
- **次要内容更安静**：次要区块不填底色、不加阴影，标题用 13px；侧栏（其他扫描、系统对象、权限与能力）放在右侧 300px 栏，窄窗口时移到正文之后。
- **导语不超过一句**：每页的引导文字最多一句短句；解释放进“了解更多”（`learnMore()`），机器信息（代码、读取方式、英文原始消息、扫描编号）放进“技术详情”（`techBlock()`）。
- **主文字永远是中文**：问题与拒绝原因一律经 `lib/codes.ts` 翻成中文；表里没有的代码显示“未识别的问题（代码 x）”，原始消息只在折叠的“技术详情”中。
- **路径从中间截断**：开头（盘符、前几级）和最后一级名称保持可读，完整路径在悬停提示、读屏文字和复制内容里（`pathText()`）。
- **未知就是“未知”**：大小未知显示“未知”，部分已知显示“至少 X”，从不显示 0（`sizeLabel()` / `sizeEl()`）。
- **徽标用白话**：未通过发布前验收的工具在分区栏显示“实验功能”（提示：该功能尚未通过发布前验收，仅供本机评估），关闭时显示“默认关闭”；门禁编号只在“设置 › 实验功能”和“了解更多”里出现。

### 磁盘（P3）

页面顺序：标题 → 位置（面包屑）→ 一行安静的元信息（状态词、时间、“面积与排序按逻辑大小”）→ 结果不完整时的一条 `stateLine` → 图（上方是此文件夹的已知大小，页面唯一的大数字；未知数量单独列出）→ 表格；详情栏在图的右边。

| 状态（`diskView()`） | 显示 | 下一步 | 不显示 |
| --- | --- | --- | --- |
| 没有扫描 | 空状态“还没有可浏览的结果” | 选择扫描范围 | 图、表、面包屑 |
| 读取中 / 状态属于另一份扫描 | “正在读取扫描记录…” | — | 旧扫描的图 |
| 无法读取状态 | 失败横幅（中文原因） | 选择扫描范围 | 图、表 |
| 进行中 / 正在停止（未发布） | 进行中横幅 + 不确定进度条 | 查看扫描进度 | 任何大小与排名（不读暂存数据） |
| 失败 | 失败横幅，原因来自代码表 | 根被拒绝：选择扫描范围；其他：查看原因 | 图、表 |
| 发布但没有条目 / 未发布就结束 | 已停止横幅 | 查看原因 / 选择扫描范围 | 空图 |
| 完成 | 图 + 表 | — | 状态行 |
| 部分完成 | 图 + 表，上方状态行“N 处位置没有读到，大小记为未知” | 查看原因（概览） | — |
| 部分完成 + 等待 macOS 授权 | 同上，虚线圆“等待 macOS 授权” | 查看原因 | — |
| 已取消 / 已中断 | 图 + 表，短横状态行“这里只有停止前确认的部分” | — | — |

不能浏览时，下面列出可以浏览的其他扫描（安静列表，路径中间截断）。

**图 ↔ 表联动**（纯函数在 `lib/diskModel.ts`，`diskModel.test.ts` 覆盖）：

- 表格的当前行点亮它的图块；被合并进“其他 N 项”的条目点亮合并图块；大小未知、没有图块的条目什么都不点亮（不会留着旧图块）。点亮 = 内侧 2 px 强调色环 + 右上角圆点，其余图块降低饱和度（文字对比度不变）。
- 选中图块（点击或方向键）让表格定位同一个条目（同一 `entry_id`，必要时按同一查询继续分页），详情栏随之更新；合并图块定位其中最大的一项并说明；“其余”图块提示在表格中继续加载。
- 鼠标悬停表格行时，对应图块显示浅色环。
- 图是一个 Tab 停靠点（`role=listbox`，图块为 `option`，`aria-activedescendant` 指向当前图块）：方向键按位置移到相邻图块，Home / End 到最大 / 最小，Enter 打开文件夹，空格选择，Backspace 或 Alt+↑ 返回上一级；焦点留在图里。表格键盘不变（↑↓、PageUp/Down、Home/End、空格选择、Enter 打开、Backspace / Alt+↑ 上一级）。
- 面包屑：根是完整路径（中间截断），层级超过 5 时保留根和最后 3 级，中间折成“…”（点击展开，提示里是被折叠的层级）；不在根时前面有“返回上一级”按钮。

**详情栏层级**：它是什么（类别色块 + 类型词、名称、可复制的路径）→ 有多大（逻辑大小大数字；“分配 X”；子项未知数）→ 能做什么（打开此文件夹、选择、在文件管理器中显示、AI 诊断）→ “可手动清理”提示（安静：点线圆 + 灰字，不是徽标）→ 技术详情（大小依据、精确字节、身份、条目编号）。表格里的“可手动清理”同样是点线圆 + 灰字；占比是行底分隔线上的一段填充，不在名称下划线。

### 清理候选（P4）

顺序：页头 → 摘要（一句“按规则找到 N 个候选”+ 低风险与需审阅合计；`summaryStrip` 四格：低风险 / 需要审阅 / 待判断 / 不可选择，各自数量与已知大小，点击跳到该组）→ 状态行（规则已更新、只覆盖部分范围）→ 分组（组头：形状 + 词、数量、已知大小、未知数）→ 行（名称、中间截断路径、理由；大小“至少 X”与“N 项未知”分开）。处理方式卡片带可撤销徽标；选择“永久删除”后卡片、生成按钮与底部选择栏的主按钮都换成危险样式。构建产物与安装包页用同一个摘要行。

### 计划审阅（P4）

页面唯一的主元素是**计划陈述**：一句话（`planSentence()`）→ 数量行（对象、已知大小、来源、规则数，用细竖线分隔）→ 可撤销徽标 + 恢复方式 → 空间说明。然后才是“范围与依据”（做什么、来源扫描、规则版本、有效期、不包含的内容）和完整清单；授权栏在右侧，窄窗口时排在依据之后、清单之前。

| 模式 | 一句话 | 徽标 | 边缘 |
| --- | --- | --- | --- |

| 永久删除 | 永久删除 N 个文件 | 无法撤销（斜纹、警告三角）；清单标题旁再标“每一项都无法撤销”；批准按钮“批准这份永久删除计划”与执行按钮带警告三角，默认焦点不落在它们上 | 10 px 砖红斜纹 |
| 恢复 / 永久清空隔离项 | 把 N 个隔离对象恢复到原位置 / 永久清空 N 个隔离对象 | 不需要撤销 / 无法撤销 | 强调色 / 斜纹 |
| 卸载、更新、维护 | 原有的审阅句 | CleanManager 无法撤销 | 警告色 |

| 授权状态（`authView()`） | 授权栏 |
| --- | --- |
| 等待批准 | 摘要印章 + 输入前 8 位 + 批准按钮（输入不符时按钮不可用；拒绝原因以中文错误行显示） |

### 缩放与窄窗口（P5）

在 1440 px 窗口下用设备缩放 100 / 125 / 150 %（CSS 宽度 1440 / 1152 / 960 px）和 390 px 宽检查磁盘、清理、计划审阅、执行结果、维护、设置：

## 界面文字与语言（LIF-05）

桌面界面的每一句人类可读文字都来自两份资源：`apps/desktop/src/i18n/zh-CN.ts`（简体中文，保留此前页面上的原文，逐字）和 `apps/desktop/src/i18n/en.ts`（英文）。两份资源的键相同；`en.ts` 的类型是 `Record<MessageKey, string>`，少一个键或多一个键都无法编译。代码、状态值、字段名和 CLI/JSON 输出从不翻译。

**取文字**：`t(key, params)`（`src/i18n/index.ts`）。键按文件与表命名：`cleanup.summary`（页面词表 `CLEANUP_TEXT.summary`）、`words.modeLabel.quarantine`（`MODE_LABEL.quarantine`）、`codes.issueText.<code>`（代码表）、`common.*`（多个页面共用的同一句话）。以 `@macos` 结尾的键是前一个键在 macOS 上的读法，`t` 在 macOS 上自动选用；`platform.*` 是平台惯用语表（`PLATFORM_WORDS`）的来源。于是一句话可以同时按平台与语言变化：

| | Windows | macOS |
| --- | --- | --- |
| 简体中文 | `platform.bin` → 回收站 | `platform.bin@macos` → 废纸篓 |
| English | `platform.bin` → Recycle Bin | `platform.bin@macos` → Trash |

**消息语法**（ICU MessageFormat 的子集，由 Intl 实现，没有新依赖）：`{name}` 原样插入值；`{n, number}` 按当前语言分组数字；`{n, plural, =0 {No files} one {# file} other {# files}}` 按 `Intl.PluralRules` 选复数形式，`#` 是分组后的数字。中文通常写 `{n, number} 个文件`，英文写复数形式。

**格式**：数字用 `formatNumber`/`groupDigits`（Intl.NumberFormat）；时间用 `formatTime`（Intl.DateTimeFormat：中文 `2026-10-22 14:05`，英文 `Oct 22, 2026, 2:05 PM`）；字节大小在两种语言中都用二进制单位（KiB/MiB/GiB）。

**切换不需要重启**：页面词表与代码表的条目是读取资源的 getter；页面在 `update()` 中重绘时读到新语言。构造时建好、之后不再重绘的元素（外壳导航、页面标题、长操作进度条）用 `live()` / `liveChildren()`（`lib/dom.ts`）绑定，语言切换后由外壳统一刷新。不要在模块顶层把资源文字算成常量（`const X = t(…)`、`{ ...TABLE }`），那样会停在启动时的语言。

**宿主文字**：主文字永远来自“代码 → 资源”；宿主发来的原始消息只放在“技术详情”或提示里（`isRawHostText`：中文界面按是否含中文判断，英文界面按是否是资源文字判断）。宿主固定用中文命名的少数对象（扫描范围页的建议位置、内置电池）按其类别换成资源文字（`rootLabel`、`batteryName`）。

**设置**：设置 › 界面语言提供“跟随系统”（默认：`navigator.language` 以 zh 开头为简体中文，否则 English）、“简体中文”、“English”；选择保存在 `localStorage` 的 `cm.lang`（与主题的 `cm.theme` 并列，跟随系统时不保存），立即生效并设置 `<html lang>`。两个语言名称在两种语言下都写成它自己的语言。

**添加或修改文字**：

1. 在 `zh-CN.ts` 和 `en.ts` 中加同一个键，两边使用同一组占位符；英文写自然、简洁的句子，术语见下表；平台不同的句子再加 `键@macos`（两种语言都要）。
2. 代码中写 `t('键', { … })`，不要写中文字面量；词表条目写成 getter（`get title() { return t('…'); }`）。
3. 运行 `npx vitest run src/i18n`：守卫测试在以下情况失败——一个键只在一份资源中、占位符不一致、值为空、英文中出现中文或全角标点、`src/views/**`、`src/main.ts` 或 `src/lib/**` 的字符串字面量中出现中文（注释不算）、某个键没有被任何代码使用。

## 统一选择 / 审阅 / 结果（GUI-09/10）

`views/kit.ts` 提供可复用组件，清理（规则清理）、构建产物、安装包、卸载残留、维护任务、更新与旧下载审阅共用同一套选择 → 审阅 → 结果：

- **三档徽标** `tierBadge()`：低风险（实心圆）/ 需审阅（半圆）/ 已阻止（斜杠方框），与风险分组同一套形状。
- **底部选择栏** `selectionBar()`：已选数量、已知大小（部分未知时为“至少 X”）、未知项单独计数、跨多个位置时提示“每个位置一份计划”，主按钮进入同一计划审阅。
- **摘要行** `summaryStrip()`：分组之前先给每组的数量与已知大小（清理候选、构建产物、安装包）。
- **处理方式** `modeOptions()` / `commonModes()`：只提供所有已选对象都允许的方式，并说明空间与恢复；每张卡片带可撤销徽标 `undoBadge()`，选中“永久删除”时卡片左缘为斜纹。
- **结果**：执行结果页对未确认的结果显示“至少 X”和未计入的项目数；启动项、卸载、更新、进程与维护结果不显示空间数字。
- **流程步骤** `stageSteps()`：只用于真正有先后的流程（卸载：1 卸载程序 → 2 残留），出现在卸载页、残留审阅与两份计划的审阅页。
- **六种维护结果** `outcomeMark()` / `outcomeTally()`：已执行（实心圆）、无需改变（空心圆）、需要跟进（实心菱形）、已跳过（空心菱形）、不可用（短横）、失败（方块）；六项计数始终全部显示，任何跳过或需要跟进时都不显示“全部完成”。
- 从不预先勾选；创建计划不执行任何操作；所有写入都经过单次审阅令牌 + 输入摘要前 8 位的批准。

## 权限就绪与长操作（GUI-13/14）

- 扫描、构建产物/安装包发现、手选回收站、启动项修改和计划执行开始前调用宿主 `readiness`，一次说明缺口（数据目录、保护清单、管理员权限、备份/还原特权、回收站）及影响，允许以当前权限继续；阻断项（数据目录、保护清单）不允许继续。同一操作、同样的缺口在本次会话只说明一次，任务开始后不再弹出权限请求。
- 长操作显示阶段文字与已用时间，分母未知时只显示不确定进度条，不显示百分比（`LongProgress`）。
- 异步结果带生成序号（`lib/gate.ts` 的 `RequestGate.latest()` 与 `SubjectGate`）：旧请求或旧对象的结果到达时被丢弃，不会覆盖当前视图；`lib/generation.test.ts` 覆盖“切换对象后旧扫描结果返回”的场景。

## 响应式与无障碍

- 宽度 >900 px：带文字的工具栏；≤900 px：图标栏（名称保留给读屏与提示）；≤640 px：顶部一行五个工具 + “更多”菜单（扩展、快捷键、主题）。在 1440 / 1024 / 390 / 320 px 下页面无横向滚动。
- 键盘：所有入口为原生按钮，焦点可见（2 px 强调色描边），对话框为原生 `<dialog>`（Esc 关闭、焦点进入）；导航按钮带 `aria-current` 与 `aria-keyshortcuts`。
- 状态变化（扫描从进行中变为完成、部分完成、失败等）由概览通过全局 `aria-live` 播报一次“标题。一句话”；执行结束由全局通知播报一次，执行结果页在只读核对完成后读出新的结果标题与一句话；进度计数不播报，避免刷屏。被截断的路径对读屏器读出完整路径。
- 磁盘图是一个键盘停靠点（方向键 / Home / End / Enter / 空格 / Backspace），与表格同步当前条目；详情栏是 `aria-live="polite"` 区域。永久删除在徽标、陈述边缘、按钮上都有图标和词，不只靠颜色。
- `prefers-reduced-motion` 关闭所有动画；`forced-colors` 下当前导航项、分区标签、标志、选择栏、指标卡片使用系统颜色描边。
