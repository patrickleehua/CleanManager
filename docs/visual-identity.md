# 视觉标识、信息架构与资源清单

最近更新：2026-10-22。对应 OpenSpec `add-mole-parity-suite` 任务 16.1–16.5 与 GUI-08..14。实现位于 `apps/desktop/src`：令牌在 `styles.css`，图标与标志在 `lib/dom.ts`，导航与快捷键在 `lib/nav.ts`，平台惯用语在 `lib/platform.ts`，统一选择/审阅/结果组件在 `views/kit.ts`，状态横幅、问题行、路径等共享展示组件在 `views/ui/`，代码 → 中文表在 `lib/codes.ts`。

## 设计方向

CleanManager 是一个“先看后删”的磁盘与系统整理工具，主要用户在 Windows 上整理自己的文件，同时需要随时知道哪些东西不会被动。视觉延续 suite-v3 原型已建立的基调：

- **颜色**：几乎中性的灰色纸面（`--bg #f5f6f5`）、白色面板、深松绿强调色（`--accent #2e7a62`，唯一有饱和度的品牌色），警告用陶土棕（`--warn #8a6327`），危险用砖红（`--danger #a84d3e`）。深色主题是同一套色相的低亮度版本，不是反相。
- **字体**：使用操作系统自带字体（Windows：Segoe UI Variable / Microsoft YaHei UI；macOS：PingFang SC），不打包任何字体文件；数字使用等宽数字（`tabular-nums`）。
- **唯一的醒目元素**：左侧“工具栏”——原创标志加五个工具图标，当前工具以松绿刻痕和面板底色标出。页面本身保持安静：同一种页头、同一种工作区 + 右侧决定栏、同一种底部选择栏。
- **状态从不只靠颜色**：每个状态都有形状 + 文字（实心圆=低风险、半圆=需审阅、斜杠方框=已阻止；结果条的成功/跳过/失败/未知各有形状）。

### 信息分层规则（P0）

- **一页一个主信息**：页面顶部只有一个主元素（概览上是状态横幅：形状 + 含状态词的标题 + 一句话 + 下一步）。其余内容按“主 → 次 → 细节”往下排。
- **次要内容更安静**：次要区块不填底色、不加阴影，标题用 13px；侧栏（其他扫描、系统对象、权限与能力）放在右侧 300px 栏，窄窗口时移到正文之后。
- **导语不超过一句**：每页的引导文字最多一句短句；解释放进“了解更多”（`learnMore()`），机器信息（代码、读取方式、英文原始消息、扫描编号）放进“技术详情”（`techBlock()`）。
- **主文字永远是中文**：问题与拒绝原因一律经 `lib/codes.ts` 翻成中文；表里没有的代码显示“未识别的问题（代码 x）”，原始消息只在折叠的“技术详情”中。
- **路径从中间截断**：开头（盘符、前几级）和最后一级名称保持可读，完整路径在悬停提示、读屏文字和复制内容里（`pathText()`）。
- **未知就是“未知”**：大小未知显示“未知”，部分已知显示“至少 X”，从不显示 0（`sizeLabel()` / `sizeEl()`）。
- **徽标用白话**：未通过发布前验收的工具在分区栏显示“实验功能”（提示：该功能尚未通过发布前验收，仅供本机评估），关闭时显示“默认关闭”；门禁编号只在“设置 › 实验功能”和“了解更多”里出现。

### 概览的状态矩阵（P2）

| 状态 | 横幅 | 先显示 | 下一步 | 不显示 |
| --- | --- | --- | --- | --- |
| 进行中 / 准备中 / 正在停止 | 进行中（圆环） | 已发现条目、已用时间、不确定进度条 | 取消扫描 | 大小、覆盖、浏览、清理候选、系统对象 |
| 完成 | 完成（实心圆） | 已知空间（大数字）与条目数 | 浏览磁盘、查看清理候选 | 缺口面板（除非有大小未知的条目） |
| 部分完成 | 部分完成（半圆） | 没有读到的位置（中文问题行），然后“已读到的部分：至少 X” | 浏览磁盘、查看清理候选、重新扫描 | — |
| 部分完成 + 等待 macOS 授权 | 等待授权（虚线圆） | 等待授权的位置（沙漏行排第一） | 重新扫描（主按钮）、浏览已读到的部分 | — |
| 失败 | 失败（方块） | 原因（中文一句）与路径 | 文件 / 链接 / 不存在的根：重新选择扫描范围；其他原因：重新扫描；另有“查看上一次的扫描结果”链接 | 覆盖与缺口、浏览磁盘、清理候选、系统对象、侧栏、用时 |
| 已取消 / 已中断 | 已停止（短横） | 已保留的条目数与“至少 X” | 重新扫描、浏览已保留的结果 | 清理候选、系统对象 |
| 没有扫描 | 空状态 | “还没有扫描结果” | 选择扫描范围 | 系统对象 |

扫描范围页（P01）：选中的位置、开始按钮和“选择其他文件夹…”在同一面板；选到文件或链接时，宿主返回的 `not_a_directory` / `root_is_link` 在开始按钮上方以中文错误框显示（读屏会播报），原来的选择被清空，不会改去扫描别的位置；最近的扫描在右侧栏，可直接打开结果。

### 浏览器预览开关

`npm run dev` 后打开 http://127.0.0.1:1420/ ，URL 参数只在预览（模拟后端）中有效：

| 参数 | 作用 |
| --- | --- |
| `?platform=macos` | macOS 文字、macOS 路径与 macOS 宿主的回答（`lib/mockMac.ts`） |
| `?scan=completed` | 完成的扫描（没有缺口） |
| `?scan=partial`（默认） | 部分完成：一处权限不足、一个大小未知 |
| `?scan=partial-pending` | 部分完成且 macOS 授权对话框尚未回答（与 `?platform=macos` 一起看） |
| `?scan=failed-file` / `failed-link` / `failed-missing` | 根是文件 / 链接 / 不存在 |
| `?scan=failed-unknown` | 失败且代码不在表中（显示“未识别的问题”） |
| `?scan=cancelled` / `interrupted` | 取消 / 中断，保留了部分结果 |
| `?scan=running` | 正在运行的扫描（可以点“取消扫描”） |
| `?scan=none` | 还没有任何扫描 |
| `?choose=file` / `?choose=link` | 扫描范围页第一次“选择其他文件夹…”返回文件 / 链接，显示提交前的校验错误 |

参数可以和页面锚点组合，例如 `?platform=macos&scan=partial-pending#overview`、`?choose=file#scope`。

## 信息架构（GUI-08 / D14）

两个平台的顺序、名称、快捷键完全相同。平台不支持或尚未通过门禁的功能保留在原位，显示能力说明页（它会做什么、为什么现在不可用、规格编号与门禁、上线后仍遵守的安全约束、现在可用的命令行），不会消失或显示空白页。

| 工具 | 分区（顶部分区栏） | 状态 |
| --- | --- | --- |
| 清理 ⌃1 | 规则清理（原“清理”页）· 构建产物 · 安装包 · 回收站 | 前三项可用；回收站页说明手选移入回收站的入口（分析 › 磁盘），浏览与永久删除回收站项目暂为“仅命令行” |
| 软件 ⌃2 | 应用（原“应用”页）· 卸载 · 更新 · 启动项 | Windows 下四个分区都可用（更新只检测 winget/商店/Scoop，计划任务类启动项只读）。卸载分两份计划（卸载程序 → 残留），强制结束仍在运行的进程（`--end-running` + END）只在终端；更新只在点击时检查，关闭后不发任何请求 |
| 优化 ⌃3 | 维护任务 · 性能诊断 | 可用。需要管理员的任务在执行开始时由 Windows 询问一次（与 CLI 相同的单次授权工作进程），拒绝只跳过这些任务；诊断只读 |
| 分析 ⌃4 | 概览 · 磁盘（含手选移入回收站）· 空间洞察 · 扫描范围 | 可用 |
| 状态 ⌃5 | 系统状态 · 进程 · 常驻工具 | 可用。结束进程只能通过针对单个进程的计划；持续高占用提醒默认关闭，只在系统状态页打开时检查；常驻工具的托盘默认关闭，菜单只有读数与打开页面（见[常驻工具](resident-utilities.md)） |
| 扩展 | 计划 ⌃6 · 活动 ⌃7 · 恢复 ⌃8 · Agent ⌃9 · AI 诊断 ⌃0 · 设置 ⌃, | 计划/活动/恢复是原“活动”页的三个标签（含扫描记录），Agent 为“仅命令行”说明页 |

Windows 用 Ctrl，macOS 用 ⌘；应用内按 `?` 显示同一张表。

| 按键 | 作用 |

## 平台惯用语（GUI-12）

同一份计划在两个平台的字段与结果含义相同（模式键始终是 `trash`），只有词语按平台表替换（`lib/platform.ts`）：

| 概念 | Windows | macOS |
| --- | --- | --- |
| 回收站 | 回收站 / 移到回收站 | 废纸篓 / 移到废纸篓 |
| 还原方式 | 在资源管理器的回收站中还原 | 在访达的废纸篓中“放回原处” |
| 显示对象 | 在资源管理器中显示 | 在访达中显示 |
| 快捷键修饰键 | Ctrl | ⌘ |
| 启动项系统入口 | 任务管理器 › 启动应用 | 系统设置 › 通用 › 登录项与扩展 |
| 常驻组件 | 托盘（通知区域） | 菜单栏图标 |

## 统一选择 / 审阅 / 结果（GUI-09/10）

`views/kit.ts` 提供可复用组件，清理（规则清理）、构建产物、安装包、卸载残留、维护任务、更新与旧下载审阅共用同一套选择 → 审阅 → 结果：

- **三档徽标** `tierBadge()`：低风险（实心圆）/ 需审阅（半圆）/ 已阻止（斜杠方框），与风险分组同一套形状。
- **底部选择栏** `selectionBar()`：已选数量、已知大小（部分未知时为“至少 X”）、未知项单独计数、跨多个位置时提示“每个位置一份计划”，主按钮进入同一计划审阅。
- **处理方式** `modeOptions()` / `commonModes()`：只提供所有已选对象都允许的方式，并说明空间与恢复。
- **结果**：执行结果页对未确认的结果显示“至少 X”和未计入的项目数；启动项、卸载、更新、进程与维护结果不显示空间数字。
- **流程步骤** `stageSteps()`：只用于真正有先后的流程（卸载：1 卸载程序 → 2 残留），出现在卸载页、残留审阅与两份计划的审阅页。
- **六种维护结果** `outcomeMark()` / `outcomeTally()`：已执行（实心圆）、无需改变（空心圆）、需要跟进（实心菱形）、已跳过（空心菱形）、不可用（短横）、失败（方块）；六项计数始终全部显示，任何跳过或需要跟进时都不显示“全部完成”。
- 从不预先勾选；创建计划不执行任何操作；所有写入都经过单次审阅令牌 + 输入摘要前 8 位的批准。

## 权限就绪与长操作（GUI-13/14）

- 扫描、构建产物/安装包发现、手选回收站、启动项修改和计划执行开始前调用宿主 `readiness`，一次说明缺口（数据目录、保护清单、管理员权限、备份/还原特权、回收站）及影响，允许以当前权限继续；阻断项（数据目录、保护清单）不允许继续。同一操作、同样的缺口在本次会话只说明一次，任务开始后不再弹出权限请求。
- 长操作显示阶段文字与已用时间，分母未知时只显示不确定进度条，不显示百分比（`LongProgress`）。
- 异步结果带生成序号（`lib/gate.ts` 的 `RequestGate.latest()` 与 `SubjectGate`）：旧请求或旧对象的结果到达时被丢弃，不会覆盖当前视图；`lib/generation.test.ts` 覆盖“切换对象后旧扫描结果返回”的场景。

## 响应式与无障碍

- 宽度 >900 px：带文字的工具栏；≤900 px：图标栏（名称保留给读屏与提示）；≤640 px：顶部一行五个工具 + “更多”菜单（扩展、快捷键、主题）。在 1440 / 1024 / 390 / 320 px 下页面无横向滚动。
- 键盘：所有入口为原生按钮，焦点可见（2 px 强调色描边），对话框为原生 `<dialog>`（Esc 关闭、焦点进入）；导航按钮带 `aria-current` 与 `aria-keyshortcuts`。
- 状态变化（扫描从进行中变为完成、部分完成、失败等）由概览通过全局 `aria-live` 播报一次“标题。一句话”；进度计数不播报，避免刷屏。被截断的路径对读屏器读出完整路径。
- `prefers-reduced-motion` 关闭所有动画；`forced-colors` 下当前导航项、分区标签、标志、选择栏、指标卡片使用系统颜色描边。
