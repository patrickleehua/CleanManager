# 视觉标识、信息架构与资源清单

最近更新：2026-10-15。对应 OpenSpec `add-mole-parity-suite` 任务 16.1–16.5 与 GUI-08..14。实现位于 `apps/desktop/src`：令牌在 `styles.css`，图标与标志在 `lib/dom.ts`，导航与快捷键在 `lib/nav.ts`，平台惯用语在 `lib/platform.ts`，统一选择/审阅/结果组件在 `views/kit.ts`。

## 设计方向

CleanManager 是一个“先看后删”的磁盘与系统整理工具，主要用户在 Windows 上整理自己的文件，同时需要随时知道哪些东西不会被动。视觉延续 suite-v3 原型已建立的基调：

- **颜色**：鼠尾草色纸面（`--bg #f7f8f5`）、白色面板、深松绿强调色（`--accent #2e7a62`），警告用陶土棕（`--warn #8a6327`），危险用砖红（`--danger #a84d3e`）。深色主题是同一套色相的低亮度版本，不是反相。
- **字体**：使用操作系统自带字体（Windows：Segoe UI Variable / Microsoft YaHei UI；macOS：PingFang SC），不打包任何字体文件；数字使用等宽数字（`tabular-nums`）。
- **唯一的醒目元素**：左侧“工具栏”——原创标志加五个工具图标，当前工具以松绿刻痕和面板底色标出。页面本身保持安静：同一种页头、同一种工作区 + 右侧决定栏、同一种底部选择栏。
- **状态从不只靠颜色**：每个状态都有形状 + 文字（实心圆=低风险、半圆=需审阅、斜杠方框=已阻止；结果条的成功/跳过/失败/未知各有形状）。

## 信息架构（GUI-08 / D14）

两个平台的顺序、名称、快捷键完全相同。平台不支持或尚未通过门禁的功能保留在原位，显示能力说明页（它会做什么、为什么现在不可用、规格编号与门禁、上线后仍遵守的安全约束、现在可用的命令行），不会消失或显示空白页。

| 工具 | 分区（顶部分区栏） | 状态 |
| --- | --- | --- |
| 清理 ⌃1 | 规则清理（原“清理”页）· 构建产物 · 安装包 · 回收站 | 前三项可用；回收站页说明手选移入回收站的入口（分析 › 磁盘），浏览与永久删除回收站项目暂为“仅命令行” |
| 软件 ⌃2 | 应用（原“应用”页）· 卸载 · 更新 · 启动项 | Windows 下四个分区都可用（更新只检测 winget/商店/Scoop，计划任务类启动项只读）。卸载分两份计划（卸载程序 → 残留），强制结束仍在运行的进程（`--end-running` + END）只在终端；更新只在点击时检查，关闭后不发任何请求 |
| 优化 ⌃3 | 维护任务 · 性能诊断 | 可用。需要管理员的任务在执行开始时由 Windows 询问一次（与 CLI 相同的单次授权工作进程），拒绝只跳过这些任务；诊断只读 |
| 分析 ⌃4 | 概览 · 磁盘（含手选移入回收站）· 空间洞察 · 扫描范围 | 可用 |
| 状态 ⌃5 | 系统状态 · 进程 · 常驻工具 | 可用。结束进程只能通过针对单个进程的计划；持续高占用提醒默认关闭，只在系统状态页打开时检查；常驻工具的托盘默认关闭，菜单只有读数与打开页面（见[常驻工具](resident-utilities.md)） |
| 扩展 | 计划 ⌃6 · 活动 ⌃7 · 恢复 ⌃8 · Agent ⌃9 · AI 诊断 ⌃0 · 设置 ⌃, | 计划/活动/恢复是原“活动”页的三个标签（含扫描记录），Agent 为“仅命令行”说明页 |

表中的“可用”只表示 Windows 开发构建里该页面已接入核心，不表示能力已通过门禁或已发布：G1–G4（任务 18.1–18.4）都还没有通过，macOS 上这些页面显示能力说明页。逐项状态见 [对标完成度复核](../openspec/changes/add-mole-parity-suite/parity-review.md)。

原页面全部保留：概览、磁盘、扫描范围归入“分析”；清理候选为“清理 › 规则清理”；应用为“软件 › 应用”；活动的执行/计划/扫描/隔离区标签分别由“活动”“计划”“恢复”进入；AI 诊断与设置在扩展组。计划审阅与执行结果页在打开它们的工具下高亮。

### 快捷键

Windows 用 Ctrl，macOS 用 ⌘；应用内按 `?` 显示同一张表。

| 按键 | 作用 |
| --- | --- |
| Ctrl/⌘ + 1…5 | 清理、软件、优化、分析、状态（回到该工具上次打开的分区） |
| Ctrl/⌘ + 6、7、8、9、0 | 计划、活动、恢复、Agent、AI 诊断 |
| Ctrl/⌘ + , | 设置 |
| Ctrl/⌘ + PageUp / PageDown | 当前工具的上一个 / 下一个分区 |
| ? | 快捷键表（焦点在输入框时不触发） |
| Esc | 关闭对话框、“更多”菜单 |

另一平台的修饰键不会触发任何动作；对话框打开时导航快捷键暂停。`lib/nav.test.ts` 验证顺序、名称、键位唯一性以及两平台键位一致。

| 回收站 | 回收站 / 移到回收站 | 废纸篓 / 移到废纸篓 |
| 还原方式 | 在资源管理器的回收站中还原 | 在访达的废纸篓中“放回原处” |
| 显示对象 | 在资源管理器中显示 | 在访达中显示 |
| 快捷键修饰键 | Ctrl | ⌘ |
| 启动项系统入口 | 任务管理器 › 启动应用 | 系统设置 › 通用 › 登录项 |

## 统一选择 / 审阅 / 结果（GUI-09/10）

`views/kit.ts` 提供可复用组件，清理（规则清理）、构建产物、安装包、卸载残留、维护任务、更新与旧下载审阅共用同一套选择 → 审阅 → 结果：

- **三档徽标** `tierBadge()`：低风险（实心圆）/ 需审阅（半圆）/ 已阻止（斜杠方框），与风险分组同一套形状。
- **底部选择栏** `selectionBar()`：已选数量、已知大小（部分未知时为“至少 X”）、未知项单独计数、跨多个位置时提示“每个位置一份计划”，主按钮进入同一计划审阅。
- **处理方式** `modeOptions()` / `commonModes()`：只提供所有已选对象都允许的方式，并说明空间与恢复。
- **结果**：执行结果页对未确认的结果显示“至少 X”和未计入的项目数；启动项、卸载、更新、进程与维护结果不显示空间数字。
- **流程步骤** `stageSteps()`：只用于真正有先后的流程（卸载：1 卸载程序 → 2 残留），出现在卸载页、残留审阅与两份计划的审阅页。
- **六种维护结果** `outcomeMark()` / `outcomeTally()`：已执行（实心圆）、无需改变（空心圆）、需要跟进（实心菱形）、已跳过（空心菱形）、不可用（短横）、失败（方块）；六项计数始终全部显示，任何跳过或需要跟进时都不显示“全部完成”。
- 从不预先勾选；创建计划不执行任何操作；所有写入都经过单次审阅令牌 + 输入摘要前 8 位的批准。

## 权限就绪与长操作（GUI-13/14）

- 扫描、构建产物/安装包发现、手选回收站、启动项修改和计划执行开始前调用宿主 `readiness`，一次说明缺口（数据目录、保护清单、管理员权限、备份/还原特权、回收站）及影响，允许以当前权限继续；阻断项（数据目录、保护清单）不允许继续。同一操作、同样的缺口在本次会话只说明一次，任务开始后不再弹出权限请求。
- 长操作显示阶段文字与已用时间，分母未知时只显示不确定进度条，不显示百分比（`LongProgress`）。
- 异步结果带生成序号（`lib/gate.ts` 的 `RequestGate.latest()` 与 `SubjectGate`）：旧请求或旧对象的结果到达时被丢弃，不会覆盖当前视图；`lib/generation.test.ts` 覆盖“切换对象后旧扫描结果返回”的场景。

## 响应式与无障碍

- 宽度 >900 px：带文字的工具栏；≤900 px：图标栏（名称保留给读屏与提示）；≤640 px：顶部一行五个工具 + “更多”菜单（扩展、快捷键、主题）。在 1440 / 1024 / 390 / 320 px 下页面无横向滚动。
- 键盘：所有入口为原生按钮，焦点可见（2 px 强调色描边），对话框为原生 `<dialog>`（Esc 关闭、焦点进入）；导航按钮带 `aria-current` 与 `aria-keyshortcuts`。
- `prefers-reduced-motion` 关闭所有动画；`forced-colors` 下当前导航项、分区标签、标志、选择栏、指标卡片使用系统颜色描边。
