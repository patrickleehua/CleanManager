# CleanManager 产品范围与交互设计

本文是中文产品设计提案，与 [架构分析](architecture-analysis.zh-CN.md)、[共享核心](core-architecture.md)、[规则与安全](safety-and-rules.md)、[CLI 协议草案](cli-protocol.md) 和 [路线图](roadmap.md) 配套阅读。所有页面、按钮、文案、命令及默认值均为拟议设计，不代表现有应用行为、研发完成状态或性能承诺。阶段 0 仅定义只读原型；CLI v1 是实现前草案，Schema／fixture 不是运行或平台验收证据。默认方案用于继续设计和验证，用户可以后续调整，不必先逐项决策才能开始只读原型。

## 1. 依据、证据边界与定位

### 1.1 本轮 REA 工作流与事实边界

按用户指定的 REA 工作流，先整理问题与已有证据，再把观察、推论和设计分开。依据包括架构分析、合成验证记录、官方页面，以及主线保存的 WizTree 4.33 官方 portable 清单和 PE 资源静态证据。会话初次查询摘要为空不能覆盖后续已保存的证据；以对应产物与 Evidence ID 为准。没有把这些静态结果当作运行观察、原生反编译或平台验收。

| 问题／依据 | 证据类型与结论边界 | 对产品设计的约束 |
| --- | --- | --- |
| [架构分析](architecture-analysis.zh-CN.md) | 本地设计与研究依据；技术判断沿用其限定条件 | Rust 共享核心，Tauri GUI，独立 CLI；平台能力分别适配 |
| [Mole 官网](https://mole.fit/zh/)，2026-10-14 核对 | 官网列出 Mac、Windows 入口；这是公开产品信息，不是本轮运行观察 | 不把“双平台”写成独有优势，也不声称竞争产品没有 Agent 能力 |
| [WizTree 平台对比](https://diskanalyzer.com/wiztreemac-vs-wiztree)，2026-10-14 核对 | 官方提供 WizTreeMac，并描述 Windows MFT 与 Mac 批量目录枚举的差异；未验证其实现和速度 | 两平台共享语义，允许不同后端；不移用厂商速度宣称 |
| [WizTree 4.33 静态摘要](evidence/wiztree-artifact-summary.json) 与 [REA bundle](evidence/rea-wiztree-4.33.bundle.json) | 官方 portable SHA-256 为 `38b30aab08710613d8a06a7d3dfb777e43ed436cfd7d1ff8bd33d0b5b6bd2c6d`；清单 `ev_8ee19e31856ebf5270cbad35564f722991acd2af2486eda09307885bbc9c1bdf`，PE 资源 `ev_be7c36ce7aea2b7315085aba8a5474859f3bb10e0fe380ac733eb272fd976a8f`；未运行目标 | 可证明包与资源结构，不证明扫描算法、按钮行为、性能或 CleanManager 能力 |
| [原生分析 provider 诊断](evidence/rea-native-provider-unavailable.json) | Ghidra 未配置／不可用、Java runtime 缺失、IDA 未配置；原生反编译没有取得结果 | 内部实现保持未知；不阻塞基于明确设计继续写文档，也不据此补写伪代码结论 |
| [disk-cleaner 合成验证](evidence/disk-cleaner-probe.json) | 记录限定为人工 CSV 分析，版本 `fe16728994e4599242b3fd74b2f1ebff702063a9`；没有扫描、备份或删除 | 路径含 `temp` 不能证明可删；排除子项不能被父目录操作绕过 |
| 参考代码到执行风险的推论 | 架构分析将父目录仍入选与递归执行逻辑结合提出风险；不是本轮删除实验 | 把受保护后代与目录替换列入执行器验收，不能仅修饰 UI |
| CleanManager 页面、规则、授权、恢复与默认值 | 本文设计，不是逆向发现 | 所有行为都要由路线图门禁验证；无证据的性能与兼容范围保持待验证 |

后续若补充 REA 证据，应记录目标版本／摘要、Evidence ID、观察入口、环境、覆盖范围、未知项及对应需求。静态资源只能说明存在的内容，不能直接证明点击后的行为。公开文档、源码、受控运行分别保留其证据等级；不因参考产品出现新功能而自动扩大首版范围。

### 1.2 产品承诺与目标用户

产品定位：**让人和 Agent 使用同一个核心，看清磁盘事实、理解候选项、执行范围确定的操作，并查明结果。** 不以“垃圾越多越好”“一键加速”或未经测量的秒扫作为价值表达。

| 用户 | 主要任务 | 完成标准 |
| --- | --- | --- |
| 开发者与 AI 工具用户 | 找出构建产物、下载缓存与日志，区分代码、会话和模型数据 | 能解释来源、再生成代价与保留原因；不会因目录名字或闲置时间自动删除成果 |
| 普通桌面用户 | 知道空间用在哪里，处理自己理解的候选项 | 无需终端即可完成扫描、预览、执行和结果检查；知道哪些区域未被读取 |
| CLI／Agent 使用者 | 无 GUI 地查询、生成计划、按已有授权执行 | 机器输出稳定；缺授权立即返回结构化状态；满足预授权时不反复要求人确认 |
| 需要审计与恢复的用户 | 查清谁以何种依据处理了哪些对象，尽可能恢复 | 找到计划、授权来源、逐项结果和恢复限制；不承诺批次原子回滚 |

差异化是待验证的产品假设，不是对竞争产品缺失功能的断言：

1. 人工与 Agent 可交接同一份不可变计划，使用相同风险、保护、授权与执行规则。
2. 把归属证据、再生成成本、保留理由、权限缺口和未知空间作为主要信息，而非藏在日志里。
3. 区分逻辑大小、分配大小、预计释放与实际卷空间观测，不把隔离量包装成释放量。
4. 低风险重复任务可受明确策略授权；改变范围或操作模式后重新评估授权。
5. Windows 与 macOS 对齐用户任务和结果语义，用能力状态说明差别，不承诺每个系统功能一比一相同。

## 2. 产品边界与能力对等

### 2.1 首个公开版本的范围

| 范围 | 内容 | 必要边界 |
| --- | --- | --- |
| 必须包含：磁盘分析 | 选根扫描、部分结果、目录与文件查询、过滤排序、联动 treemap 与虚拟列表 | 扫描目标只读；不跨链接或挂载点扩大范围；未知值不显示为 0 |
| 必须包含：解释与候选 | 少量实机验证过的缓存／过期临时文件规则，开发者分组，风险与收益分列 | 每条规则有精确归属与适用范围；没有通过验证的规则不得作为低风险发布 |
| 必须包含：计划与受控执行 | 不可变计划、交互授权或低风险预授权、执行前复核、取消、逐项报告 | GUI、CLI 共用核心；同一计划不得重复产生副作用 |
| 必须包含：恢复与历史 | 同卷隔离及支持时的回收站模式、隔离恢复、冲突处理、受控清空 | 隔离不腾出该卷数据空间；永久删除没有通用撤销 |
| 必须包含：独立 CLI | 能力查询、扫描、分析、计划、应用、报告、取消，JSON／JSONL | 无桌面窗口依赖；不要求安装 GUI；非交互不等于授权 |
| 必须包含：桌面管理 | 概览、磁盘、清理、只读应用清单、活动记录、设置 | GUI 在核心闭环之后交付；设置不承载独立的清理判断逻辑 |
| 后续按门禁加入 | 增量索引、更多原生扫描优化；Mole 对标能力按变更 `add-mole-parity-suite` 的门禁加入：G1 清理目录第 1 波、保护名单、构建产物、安装包、手选回收站、空间洞察；G2 五工具信息架构；G3 卸载／更新／启动项、维护、状态页；G4 托盘工具与特权 helper | 各能力单独校准与验收，不把 shell 维护伪装成精确文件计划 |
| 可选扩展 | TUI、薄 MCP、受控外部 CSV 导入、备份后删除 | 不占用首版关键路径；新增入口仍调用同一核心 |
| 不在首版 | 重复文件内容哈希、自动删除 AI 会话／模型／工作树、系统快照清理、注册表瘦身、内存加速；风扇／电池等硬件控制只作为 G4 可选特权能力 | 不因发现“大”或“旧”就推导安全性；不提供任意 shell 规则 |

通用大文件浏览不直接授予删除能力。磁盘页对未命中已验证规则的对象提供查看、定位、保护和解释；手选对象只能经 `add-mole-parity-suite` 的 manual-trash 独立计划移入回收站（人工授权、不可预授权、系统目录只读），不提供绕过规则的任意递归删除或直接永久删除。下载目录、源码、凭据、数据库、聊天记录、浏览器 IndexedDB、AI 会话、模型权重和用户配置默认保留。应用“未找到安装记录”只表示归属未明，不自动成为卸载残留。

### 2.2 入口与责任

| 入口／层 | 责任 | 不承载的职责 |
| --- | --- | --- |
| Rust 共享核心 | 扫描事实、能力判断、规则、保护路径、计划摘要、授权匹配、复核、互斥、执行日志与恢复 | 不依赖某个前端是否显示确认框 |
| Tauri GUI | 查询与呈现、键盘交互、解释影响、受控用户确认、订阅任务 | 不自行认定“安全”、拼接删除命令或重算执行规则 |
| 独立 CLI／Agent | 提供版本化机器接口与人工终端入口；Agent 负责解释和选择 | 不通过 `--yes`、模型文字或计划摘要自行授予权限 |
| Skill | 告知调用顺序、解释返回值、按已授权范围编排 | 产品规则与安全边界不能只存在于 Skill；不向 Agent 提供自批端点 |
| 可选 TUI／MCP | 适配新的交互／协议入口 | 不复制执行器或维护第二套审批模型 |

### 2.3 平台能力矩阵

以下是拟议支持方式，具体 OS 版本、CPU 架构、文件系统与限制由阶段 0 的设备证据锁定。

| 用户任务 | Windows 路径 | macOS 路径 | 统一用户语义与降级 |
| --- | --- | --- | --- |
| 扫描本地目录 | 通用遍历；NTFS 元数据后端在条件满足时启用 | 批量目录属性枚举；不要求原始 APFS 解析 | 返回同一空间字段、完整性、错误与后端说明；不能用某端不可用阻断另一端只读分析 |
| 读取受限范围 | 普通权限先扫描，需要时单独说明提升权限 | 普通文件权限、Full Disk Access、沙盒限制与提权分别说明 | “继续查看可读结果”“查看权限说明”“重新扫描该范围”；不会把 root 当作万能授权 |
| 云文件分析 | 检查占位／recall 风险 | 检查云占位与对应访问能力 | 默认不下载内容；无法保证时跳过并说明未知，用户手动下载不属于本次扫描 |
| 空间解释 | 硬链接、稀疏、压缩、系统不可见区域 | clone、快照、共享容器容量、不可见区域 | 逻辑与分配值分列；预计释放可未知；共享容量不重复相加 |
| 移入回收站／隔离 | 按目标卷、权限、平台接口探测 | 按目标卷、权限、平台接口探测 | 不支持就返回原因；不静默跨卷复制或改成永久删除 |
| 应用清单 | 安装来源、系统注册信息等归属证据 | bundle／安装来源等归属证据 | 清单只读，容量覆盖不完整时标明；共享数据不能重复算成每个应用独占 |
| 卸载／系统维护 | 卸载器／MSI／MSIX／winget／Scoop 适配，注册表先备份；固定维护任务（`add-mole-parity-suite` G3） | 应用包移入废纸篓、Homebrew 适配；固定维护任务（`add-mole-parity-suite` G3） | 能力逐项开放；操作实际范围和恢复条件单独预览 |

UI 需要展示目标范围、平台、后端、限制与建议动作。机器格式遵循 [v1 Schema 草案](../schemas/v1/protocol.schema.json)：能力项为 `name`、`state`、`reason`，状态为 `available`、`permission_required`、`unsupported`、`unverified`。UI 的“降级”“部分可用”是综合能力原因及扫描完整性的说明，不另造 v1 状态值。设置页可查看完整矩阵，普通页面只在相关操作旁显示必要解释；fixture 中的 available 不构成真实支持证明。

## 3. 所有入口共用的产品语义

### 3.1 核心对象与可追溯性

| 对象 | 用户可见信息 | 核心约束 |
| --- | --- | --- |
| 扫描会话 `scan_id` | 根目录、卷、后端、时间、已发现数量、跳过范围、完整性 | 索引版本化；取消仍保留已确认结果；扫描集合不是实时文件系统快照承诺 |
| 候选集合 `candidate_set_id` | 规则／版本、归属依据、影响、风险、再生成成本、建议操作 | 来自指定索引版本；未知归属不自动变成可删；部分扫描下只纳入证据充分的已知对象 |
| 不可变计划 `plan_id` | 明确对象清单、操作模式、限制、预计收益、创建／失效时间、摘要 | 生成后不得改写；编辑选择、模式、范围或规则版本须生成新计划 |
| 授权记录 `authorization_id` | 人工授权或策略名称／版本、覆盖范围、有效期、撤销状态 | 摘要不代表授权；授权不能扩大计划；OS 权限与产品授权分离 |
| 执行 `operation_id` | 绑定计划、调用入口、授权来源、逐项状态、时间、观测空间 | 跨进程冲突检查；一份计划的重复提交返回既有执行；不重复操作 |
| 恢复清单 | 原位置、隔离位置、对象身份、隔离时间、恢复条件与冲突 | 与执行日志关联；隔离内容不作为普通清理候选；恢复／清空也是独立计划 |

用户侧可复制 ID 供排查，但主页面用自然语言解释，不要求理解内部对象名。原始路径与显示路径分开存储；GUI 中转义特殊字符，CLI 按版本化编码输出，执行以对象身份引用，不能依赖拼接显示字符串。

### 3.2 空间数字的统一定义

| 标签 | 含义 | 不可误导的展示要求 |
| --- | --- | --- |
| 逻辑大小 | 文件内容长度，`logical_bytes` | 不等于物理占用；父子统计不重复相加 |
| 分配大小 | 系统报告的分配字节，`allocated_bytes` | 无数据为“未知”；硬链接去重口径必须显示；APFS 共享块不能由简单求和解决 |
| 预计释放 | 指定操作模式下的估计，v1 候选字段 `reclaimable_estimate_bytes` 与 `estimate_basis` | 草案为值或 null，附依据；区间是后续契约设计，不向严格 v1 擅加字段；不能一律等同所选文件大小 |
| 已隔离 | 成功移入同卷隔离区的对象数与大小 | 只是位置改变，**不会因这次同卷移动而释放这些文件的数据空间**；不计作清理收益 |
| 卷可用空间变化 | `volume_free_before_bytes`、`volume_free_after_bytes` 与 `observed_free_delta_bytes`，关联操作时间 | 可能为负或受其他进程影响；写作“观测变化”，不能声称全由本次操作造成 |
| 未覆盖／未解释空间 | 权限缺口、系统区域、快照等导致的未知 | 字节未知时不捏造面积或百分比，也不统一称为“垃圾” |

容量展示使用明确的 KiB／MiB／GiB 单位，底层保留字节；协议字节数使用 u64 范围的十进制字符串，差值允许带负号，未知为 null，UI 使用精确十进制或 BigInt，不转成有精度损失的 JSON number。若提供十进制显示则标签同步改变。APFS 同容器多个卷不能把共享空闲量相加。选中大小、预计释放、已处理大小（`processed_logical_bytes`）、卷空间变化各自独立，报告中不得合并成一个“清理了多少”。

### 3.3 操作模式与不可变计划

| 模式 | 默认建议与界面说明 | 成功／失败边界 |
| --- | --- | --- |
| 同卷隔离 | 首次人工处理的建议选项；明确显示“不立即释放空间” | 精确对象移动及清单写入可验证后才算成功；无条件支持时不可用，不改为复制后删除 |
| 平台回收站 | 平台与目标支持时供选择；恢复由实际接口能力说明 | 同卷移动不当作释放；若无法在产品内恢复则给出系统恢复指引，不显示虚假的恢复按钮 |
| 永久删除可再生内容 | 仅限已验证规则和明确授权；默认不预选 | 无通用撤销；快照、硬链接等仍可能影响释放，授权不能证明可释放量 |
| 备份后删除 | 后续能力；备份目标、容量、校验与元数据恢复范围必须明确 | 备份未验证不得删除；同卷备份不能声称腾出了数据空间 |

选择是可编辑草稿，生成后是冻结的计划。严格 `PlanBody` 字段以 v1 Schema 为准，绑定 scope、扫描 revision、规则／策略摘要、固定对象身份清单、统一模式和失效时间，按 [安全规范](safety-and-rules.md) 的 `CM-C14N-v1` 计算摘要。风险、恢复与保护说明由所绑定版本的领域资料呈现，不擅自加入严格 body。v1 每份计划只有一个 `mode`：`trash`、`quarantine` 或 `delete`；混合模式须分成不同计划。计划不能保存“执行时再遍历所有文件”一类开放集合；含受保护后代时拆成明确叶子操作或整组跳过。

计划建议有效期为生成后 15 分钟，与 CLI v1 草案及计划 fixture 对齐；这是可调整的设计值，每次执行仍必须重新核验。到期、摘要不符、卷不匹配或授权条件不满足，整份计划不启动。单个条目变化、在用、不可读或缺失，执行器按规则跳过并记录；不能现场替换成另一个条目。保护清单增加时相关对象禁止执行；保护清单缩减也不扩大旧计划。需要改变集合时生成新计划并重新匹配授权。

跨入口读取同一计划必须呈现同一 body 和摘要。独立新建计划的 ID／时间可能不同，应比较排除这些生成字段后的选择与动作语义；正式 plan digest 始终覆盖完整规范化 body，不为通过比较而删掉安全相关字段。

执行前检查链接／junction／reparse point／挂载边界、文件身份、类型、受保护后代和使用状态，能使用稳定句柄时按平台实现。只做路径规范化不足以保证安全；无法安全复核就跳过。执行中出现新文件不会进入旧计划；取消或中断也不回滚已经发生的操作。

### 3.4 授权与预授权

**只读扫描、能力查询、分析和生成计划不需要产品层删除批准。** 扫描可以写入 CleanManager 自身索引与日志，但不修改被扫描对象。操作系统仍可能要求访问许可；UI 应说明这是读取权限，不显示成“批准清理”。默认普通用户运行，不能为开始扫描先强制全盘授权或管理员运行。

写操作可以由两种路径授权：

- 用户在可信交互入口确认一份具体计划的范围、模式和影响，授权绑定其摘要及有效期。
- 用户主动启用一项有边界的低风险策略，核心对本次计划逐项核验；完整命中时直接执行并记日志，无需每次重复确认。

预授权策略必须有规则 ID 与固定版本、已解析根目录／卷、允许动作、风险上限、闲置判据、单次与累计规模限制、有效期和撤销方式。建议模板见第 10 节。默认关闭自动执行，启用动作就是对该策略范围的明确授权，不再额外套一层逐次弹窗。

策略不能包含任意 shell、模型自然语言或路径模糊匹配。未知大小、未知闲置证据、归属不足、受保护对象、系统维护、备份未验证、需要额外提权或模式改变均不自动命中。新规则／新版本不自动继承旧策略。超限时返回具体差异，不静默拆成多个批次规避累计限制。多个进程共用同一配额与授权核验。

`--non-interactive` 仅表示不等待输入；缺少授权返回 `needs_approval` 和可查看的计划。取消等待不意味着批准。Agent 没有通用“批准自己”接口。产品策略不构成对同一用户任意 shell 权限的 OS 沙盒保证；未来需要更强隔离时另设可信授权边界。

## 4. 端到端用户旅程

| 旅程 | 路径与关键动作 | 成功判据与异常出口 |
| --- | --- | --- |
| J01 首次看空间 | 欢迎／选根 → 开始只读扫描 → 磁盘页观察已知结果 → 下钻大目录 → 查看归属 | 用户能说出大目录及未知范围；无权限时继续看部分结果，不被强迫升级权限 |
| J02 处理开发缓存 | 清理页按开发工具分组 → 看规则依据与再生成代价 → 勾选 → 选模式 → 冻结计划 → 确认或命中策略 → 看结果 | 完整列出对象和模式；若选同卷隔离明确知道尚未腾空间；AI 会话／模型不混入 |
| J03 Agent 发起、人工接手 | CLI 扫描／分析 → 创建计划 → 无授权返回 `needs_approval` → 用户在 GUI 或受控 CLI 查看同一 ID → 确认 → 执行 | 人看到的是同一摘要；过期时创建新计划；GUI 不重建一份看似相同但内容不同的计划 |
| J04 重复低风险维护 | 用户创建并启用有限策略 → Agent 生成新计划 → 核心匹配 → 复核后执行 → 活动记录 | 范围内不打断用户；超限／规则升级／模式不同仅返回原因与计划，不自动放宽策略 |
| J05 权限不全 | 扫描标记部分 → 打开缺口清单 → 选择保留部分结果或查看 OS 权限说明 → 用户授予后局部重扫 | 新索引版本可追溯；先前计划不会悄悄扩大；拒绝授权仍可使用已读结果 |
| J06 中断与恢复检查 | 执行中取消或进程退出 → 活动记录显示已完成与待核对 → 对未知条目进行只读核对 → 为未处理项生成新计划 | 不重放全部任务；未知结果未核对前不允许重试同一破坏动作；已完成条目可逐项追溯 |
| J07 从隔离区恢复 | 活动记录／隔离区 → 查看原位置与条件 → 建立恢复计划 → 确认 → 逐项恢复 | 原位置冲突默认跳过，可选择另一个明确位置生成新计划；从不静默覆盖新文件 |
| J08 确实需要腾空间 | 选择已验证可再生内容并查看永久删除影响，或进入隔离区选“永久清空所选” → 新计划／授权 → 报告 | 清空隔离区与最初隔离分开授权；展示预计释放和卷空间观测，不伪造回收量 |
| J09 双平台使用 | Windows／Mac 查询当前能力 → 相同导航与任务路径 → 查看平台限制 | 相同概念、状态和授权语义；某能力不支持时解释原因与可用替代，不伪装成零项结果 |

## 6. 页面逐项规格

### P01 首次使用与扫描范围

内容：产品用途、只读扫描说明、当前卷／用户目录、最近选择范围、能力与权限提示。主按钮“开始只读扫描”，次按钮“选择文件夹”“查看能力”。默认建议当前用户目录，由用户启动；不在安装后自动扫描全盘。

| 状态 | 页面内容与允许动作 |
| --- | --- |
| 初始／未选根 | 显示推荐根与扫描边界；选根后才能开始 |
| 探测中 | 根选择仍可取消；开始按钮暂不可用，不展示虚假的磁盘大小 |
| 根有效／部分权限 | 显示可读范围与可能缺口，可立即开始；权限说明是可选入口 |
| 根不存在／卷离线／不支持 | 给出具体原因，重新选择或重新检查；无静默换根 |
| 已有匹配扫描 | 提供“查看已有结果”与“重新扫描”；说明原时间和完整性 |

### P02 概览

内容：选定卷的系统容量、最近扫描摘要、已验证候选的摘要、未覆盖范围、当前任务、最近执行。主动作随上下文为“开始扫描”“继续查看结果”或“查看计划”。每个容量卡显示数据时间与口径，不汇总共享 APFS 容量。

| 状态 | 页面内容与允许动作 |
| --- | --- |
| 无扫描 | 介绍分析入口；不显示“0 B 垃圾”或虚构健康分 |
| 扫描中 | 显示已发现数量／当前阶段，进入磁盘、取消扫描 |
| 有结果 | 展示已知范围和候选概要，进入磁盘／清理 |
| 部分／过旧／卷离线 | 提醒限制；可看历史、刷新可访问范围，不用成功勾掩盖缺口 |
| 执行后 | 分开显示处理项、隔离项、失败项和卷空间观测；进入逐项报告 |

### P03 磁盘：目录表与 treemap

内容：范围和面包屑、扫描状态、大小口径、过滤器、目录树／虚拟表、treemap、选择详情抽屉。默认按逻辑大小降序，以名称及稳定 ID 消除同值跳动；列包括名称、逻辑大小、分配大小、条目数量、类型／归属、状态。更新时间与风险在详情中解释。

动作：下钻／返回上级、搜索元数据、排序、切换大小口径、选择对象、定位文件、复制显示路径、保护、查看候选解释。仅命中可用规则时提供“加入清理草稿”；选择目录或按 Delete 不直接删除，treemap 右键也不形成旁路。

| 状态 | 页面内容与允许动作 |
| --- | --- |
| 未扫描／查询加载 | 开始扫描或显示查询骨架；旧结果继续可读且标明来自旧版本 |
| 扫描中 | 展示已发现结果与覆盖提示，不按不断变化的总量显示假完成百分比 |
| 完整／部分完成 | 完整指本次声明范围与能力内完成；部分展示错误／跳过清单，可重扫具体范围 |
| 空目录／无匹配 | 两种空态区分；无匹配可清除过滤，不提示“磁盘已干净” |
| 取消／失败 | 保留已知结果并标注终止原因；可新建扫描，不将取消改写为完成 |
| 权限／离线／查询失败 | 当前目录给出原因与重试；其他已缓存目录仍可查看 |

treemap、分页与辅助功能的完整契约见第 7 节。

### P04 清理候选与选择草稿

内容：分组、规则卡、文件明细、解释面板、草稿摘要。每组同时展示归属证据、风险、可再生成条件、预计耗时／网络成本是否未知、操作模式与恢复条件。收益未知不能参与“可释放最多”的确定排序，置于已知值之后并解释。

| 状态 | 页面内容与允许动作 |
| --- | --- |
| 无扫描／分析中 | 进入只读扫描或显示规则分析阶段，可取消分析 |
| 无候选 | “当前规则没有找到可处理项”；可查看占用和规则覆盖，不声称没有可清理数据 |
| 有候选 | 默认不勾选；可选择一个明确规则组或明细，查看影响后创建计划 |
| 部分扫描 | 仅列证据完整的候选；未读区域与依赖不完整的规则显示“待判断” |
| 在用／受保护／归属未知 | 禁止选择并显示原因；可查看保护来源或建议关闭应用后重扫，不自动结束进程 |
| 规则不适用／模式不支持 | 显示规则适用条件与能力原因；切换模式是用户选择，不自动降级 |
| 索引更新／选择失效 | 保留原草稿供对照，提示重新生成候选；不自动扩充勾选集合 |

“选择本页”与“选择当前查询全部”明确区分；后一动作由核心冻结已知集合，显示数量与范围再生成计划。受保护子项不因整组选中而被包含。AI 会话、模型和工作树显示在保留说明区域，不能用一键“开发者清理”混选。

### P05 计划详情与授权

内容：计划 ID、来源扫描、冻结时间／有效期、对象数量及可分页完整明细、规则版本、整份计划的统一模式、权限要求、保护结果、风险、预计释放、恢复限制、授权来源。摘要之外始终能查看全部对象，不以只列前若干项代替完整审阅入口。

| 状态 | 页面内容与允许动作 |
| --- | --- |
| 草稿 | 更改选择／模式后“生成计划”，此时不提供执行 |
| 已冻结、未授权 | 可审阅、导出脱敏摘要、生成修改后的新计划；用户可“确认并执行此计划” |
| 已有人工授权／匹配策略 | 显示授权来源、有效期；可执行或撤销；策略调用不额外弹逐次确认 |
| 需要 OS 权限 | 分开列出读取／执行能力需求；仅对相应动作请求；提权后仍核验计划授权 |
| 过期／内容不符／规则条件改变 | 执行禁用并解释；重新检查后生成新计划；不在旧计划上打补丁 |
| 已执行／执行中 | 进入既有执行记录；重复提交返回同一执行，不重复删除 |
| 对象已变化 | 显示复核结果；改变集合须生成新计划；允许的逐项跳过规则见执行页 |

按钮必须指明动作，如“将所选项目移入同卷隔离区”“永久删除所选可再生文件”。同卷隔离旁固定提示“此操作不立即释放空间”。不采用笼统的“优化”“修复”确认。永久操作的默认焦点落在安全动作，清晰列出无法撤销；不使用多层无意义确认替代具体计划审阅。

### P06 执行与结果详情

内容：当前阶段、固定计划条目总数、成功／失败／跳过／待核对计数、当前动作、逐项原因、日志入口、授权来源与空间观测。计划对象数是操作进度的分母，不能充当预计释放字节的完成率。

| 状态 | 页面内容与允许动作 |
| --- | --- |
| 排队／冲突 | 显示冲突操作与范围；等待或取消排队，启动前重新校验授权有效性 |
| 复核中 | 列出已变化／在用对象；可请求取消；全局条件失效则不开始写操作 |
| 执行中 | 实际已完成项持续可查；“停止后续操作”停止派发新动作，当前原生调用可能需结束 |
| 停止中 | 解释已处理项目不会自动撤销；不提前显示“已停止” |
| 全部成功 | 展示操作模式和结果；隔离成功不显示空间释放庆祝文案 |
| 部分成功／取消 | 列出成功、失败、跳过；可为仍需处理的对象重新分析并创建新计划 |
| 失败／异常中断 | 若有可能发生的操作则标“待核对”；先核对日志与对象，再决定恢复或新计划 |

可恢复项目进入隔离与恢复页。无通用“重试整个批次”按钮；不会重做已经成功的条目。实际卷空间读数失败时保留操作结果并标“空间变化未知”。

### P07 应用清单与应用详情

内容：应用名称、版本、安装来源、身份依据、已识别目录、共享数据、已知容量及未覆盖范围；可从应用进入相关候选或磁盘定位。应用容量按当前索引及归属证据显示，不递归扫描全部关联目录来凑完整数字。

| 状态 | 页面内容与允许动作 |
| --- | --- |
| 加载／清单为空 | 明确是无来源记录还是未读取；可刷新与查看来源能力 |
| 已识别 | 查看详情、相关目录和候选；首版不提供卸载操作（卸载、更新、启动项见 `add-mole-parity-suite` G3） |
| 多个来源同名／归属冲突 | 保留各身份与依据，不仅凭显示名称合并 |
| 共享数据／疑似残留 | 标记不确定性，禁止默认清理；支持保护与定位 |
| 部分权限／来源不可用 | 展示可读来源和缺口；不把缺失记录等同应用已卸载 |

后续卸载页需独立计划类型，明确外部卸载器可能自行选择对象，不能沿用“已枚举文件全部可撤销”的措辞。首版界面不放不可用的营销式“即将推出”主按钮。

### P08 活动记录

内容：扫描、计划、授权、执行、恢复记录的时间线；过滤类型、来源、卷和结果；记录之间双向跳转。状态使用核心持久化状态，不因 GUI 与 CLI 来源不同而另算“成功”。

| 状态 | 页面内容与允许动作 |
| --- | --- |
| 空历史 | 说明首次扫描入口，不虚构示例执行 |
| 正常／分页中 | 查看详情、复制 ID、导出脱敏报告；分页失败不清空已有列表 |
| 运行中／其他入口发起 | 展示来源和持久化进度；只有核心确认可取消时才开放取消 |
| 异常中断／结果未知 | 显示“需要核对”，进入只读核对流程；不自动重试删除 |
| 日志损坏／权限不可读 | 提供诊断信息，不推断任务未发生，也不覆盖原记录 |

删除历史元数据与删除隔离内容是两个不同动作。仍关联未恢复隔离项、未核对操作的日志不得被自动淘汰。导出默认最小化路径，用户可主动选择更详细内容。

### P09 隔离与恢复

内容：按卷显示隔离占用、原位置、原计划、时间、可恢复条件、缺失／损坏状态。顶部提示“同卷隔离仍占用此卷空间”。清空和恢复都是选择明确条目后生成的新计划。

| 状态 | 页面内容与允许动作 |
| --- | --- |
| 空隔离区 | 说明恢复机制与限制，不把系统回收站所有内容导入成自己的操作 |
| 可恢复 | 查看、选择、创建恢复计划；默认回原位置，不覆盖 |
| 原位置冲突 | 默认跳过；可选择另存位置并生成新恢复计划，不自动重命名到未知位置 |
| 卷离线／权限不足 | 保留清单和原卷信息，重新连接／检查权限后核验 |
| 内容缺失／身份不符 | 标记不可恢复或待核对；不从别处猜测相同文件来替代 |
| 占用偏高／达到保留提醒期 | 仅提醒查看、恢复或创建永久清空计划；不因磁盘紧张或到期自动删除 |
| 恢复／清空部分成功 | 逐项报告与日志保留；失败项仍在隔离清单，不显示全部完成 |

隔离区不是独立备份；设备损坏、外部删除、权限变化和元数据不兼容都可能影响恢复。清空授权不从“允许隔离”继承；若未来提供自动清空策略，必须作为单独且明确的永久操作授权。

### P10 设置、能力、保护与策略

内容：当前系统与后端能力、权限帮助、保护清单、预授权策略、容量单位、语言／主题、数据与导出、CLI 连接说明。隐私默认离线扫描和规则判断，不要求帐号；用户交给外部 Agent 的数据可能进入该 Agent 上下文，导出提示不能承诺永不离机。

| 状态 | 页面内容与允许动作 |
| --- | --- |
| 默认设置／无策略 | 展示可用模板但不启用自动执行；保护清单包含核心固定保护与用户自定义保护 |
| 编辑保护 | 先预览匹配范围再保存；核心重新评估待执行项；固定保护不提供一键解除 |
| 策略草稿 | 必填范围、规则版本、动作、限制、有效期；可用只读模拟查看命中及拒绝原因 |
| 策略有效／暂停／到期 | 显示使用量、最近命中、来源；可撤销；撤销阻止新的写动作派发，不宣称撤销已完成动作 |
| 策略冲突／无效／升级 | 指出具体字段，保留原记录；规则升级需要重新核定，不自动替换 |
| 权限缺失／能力未知 | 提供系统说明与重新检测，不代替用户授予 OS 权限或创建无限制提权策略 |
| 保存失败 | 保持已生效设置不变，保留草稿并说明；不能在 UI 假装已保存 |

## 7. treemap、虚拟列表与无障碍契约

### 7.1 图表与列表联动

treemap 面积默认代表逻辑大小；切换到分配大小时两种视图同时切换，标题明确说明。颜色默认表示文件类别，不表达删除安全性；风险另用文字标签和图标。用户选一个色块，列表定位同一对象；列表选中同步高亮图块。双击或 Enter 下钻，面包屑与返回上级恢复原过滤和滚动位置。

按当前目录的一层聚合生成图块，不将整个扫描的所有文件节点传给 WebView。小块合为“其他已知条目”，可进一步展开，合并不抹去其实际列表记录。选择聚合块仅定位相应列表，不能直接把不可见子项全部加入删除计划。提示框给出名称、口径、大小、占比的分母与状态，必须有键盘等价详情入口。

“占当前已知目录大小的比例”与“占整个卷的比例”分开，缺权限时不能冒充全卷占比。未知大小不分配虚构面积，在独立缺口面板中列出；已知的不可读目录元数据也须标注未递归覆盖。硬链接可以保留各路径入口，但分配汇总只按明确身份口径计数；无法去重时显示统计限制，不能声称精确物理占用。

扫描更新可改变布局。只有核心发布的带 revision 结果可参与目录查询；尚无可查询 revision 时仅显示 progress，不读取 staging 索引凑实时排名。默认在当前浏览层维持排序和选中锚点，提供“有新结果，刷新布局”，或在用户空闲时受控更新；鼠标／键盘操作期间不把图块突然移位。刷新后通过稳定 ID 恢复焦点，失去对象时说明原因。图表加载失败，目录表仍支持全部核心查询和选择。

### 7.2 虚拟列表与查询

后端按 `scan_id`、索引版本、父对象、过滤和排序查询，返回游标分页、聚合与错误。排序在全查询范围完成，不只排序当前屏幕。游标绑定查询版本，版本变化后显式刷新，不拼接两个版本导致重复或遗漏。前端只请求可视窗口与有限预取，离开目录取消过时查询，进度流有背压与合并；不得一次传输全部完整路径。

多选由稳定对象 ID 管理，离开可视区不丢选择；过滤改变后显示“已选项含当前不可见项”，用户能查看完整选集并清除。全选集合冻结在明确索引版本，不随新发现条目增长。批量候选生成和最终授权仍由核心验证，虚拟化不能成为漏审对象的理由。

### 7.3 键盘与辅助技术

- 所有操作可仅用键盘完成；Tab 导航、方向键移动／展开、Enter 查看、Space 选择、Escape 关闭详情，焦点返回触发位置。Delete 不直接执行破坏操作。
- 目录表优先使用语义化表格或树表，提供名称、展开状态、选择状态、排序、行索引和可知总数；总数未知时不伪造。虚拟化焦点行需保持可达，不因回收 DOM 丢失焦点。
- 提供可分页的辅助功能表格模式和“显示更多”控制；treemap 是增强视图，所有内容与动作都可从表格获得，不要求屏幕阅读器遍历画布坐标。
- 错误、风险、选中与权限状态均有文字；不能仅靠颜色或悬浮。焦点清晰，支持高对比、系统字体缩放、减少动画和明暗主题。200% 缩放时核心操作仍可见，横向宽表可滚动并有清晰表头。
- 扫描进度使用低频、合并的礼貌播报，不逐文件打断；完成、部分成功、取消和需要处理的错误有一次清楚播报。未知总量使用“不确定进度”语义。
- Windows 真实环境验证 Narrator，macOS 验证 VoiceOver；覆盖 WebView2／WKWebView 的键盘、输入法、树表虚拟化、弹窗焦点和全流程，无障碍验收不得只靠自动检查。

## 8. 状态机、进度与错误恢复

### 8.1 生命周期

| 对象 | 主要状态 | 关键转换条件 |
| --- | --- | --- |
| 扫描 | 排队 → 枚举 → 汇总 → 完整／部分完成；另有取消／失败 | 扫描结束且缺口已统计才能判完整性；取消不抹去已发现结果 |
| 候选分析 | 读取索引 → 评估 → 就绪／部分／失败 | 规则依赖的证据不足则待判断，不以缺值替代条件 |
| 计划 | 草稿 → 冻结；授权待定／有效／失效单独呈现 | 计划内容不随授权变化而修改；修改生成新 ID |
| 执行 | 等待 → 授权检查 → 复核 → 应用 → 成功／部分／失败／取消／待核对 | 全局前提不满足则无写入；逐项失效按规则跳过；中断后未知不视为失败后可重试 |
| 恢复／清空 | 新计划 → 同一授权与执行流程 | 与原隔离操作分别绑定；不能用原计划摘要替代新动作范围 |

上表使用产品阶段名称；机器事件沿用 v1 的 `phase=discovering|indexing|analyzing|validating|applying|stopping`，分别映射发现、索引、分析、复核、执行和停止中。UI 的排队、加载等状态不得自行加入这个枚举。扫描终态为 `completed|partial|cancelled|failed`，操作另有 `reconciliation_required`；“完整”只指声明范围内的 `verified_scope`，不是整台设备全覆盖。恢复／策略状态是内部服务及 GUI 设计，尚非 v1 新记录类型。

枚举前无法知道总量时显示阶段、已发现条目、已累计大小、经过时间和可取消状态，不显示虚构的完成率或预计剩余时间。可靠分母存在后才显示该阶段进度，阶段百分比不得误解为整个卷扫描比例。长时间无新条目仍显示任务状态与最近活动；确认无响应前不把慢路径误报为失败。

完成报告至少列出声明扫描范围、覆盖情况、动作模式、计划数量、成功／失败／跳过／待核对数量、逐项原因、恢复入口、空间观测及其限制。只有所有应执行对象得到成功且没有未解释结果时才显示“全部成功”。跳过不等于失败，二者也都不等于已清理。

### 8.2 错误动作表

下表是核心原因／用户动作设计，不是扩充 v1 顶层 `error.code` 枚举。v1 顶层仅采用协议已有错误：例如策略超限映射 `policy_denied`，不具备安全竞态能力映射 `unsupported`，I/O／空间故障映射 `io_error`；待核对用 `operation_report.status=reconciliation_required` 与逐项 `unknown`。具体原因可在逐项 `code` 或人类 `message`／`required_action` 解释；当前严格 `details` 只有 plan／operation／scope ID，新增结构字段需另版契约。`cursor_stale` 需清除旧游标并重查，不能混合 revision。Mac 无法原子约束名称变化、Windows 回收站不能满足身份约束等情况拒绝动作，不以二次检查或免责声明当作已解决竞态。

| 核心原因 | 拟议用户提示 | 用户／Agent 下一步 |
| --- | --- | --- |
| `permission_required` | “部分位置无法读取，已有结果仍可查看。” | 继续、查看缺口、访问 OS 权限说明、局部重扫 |
| `unsupported` | “此目标不支持所选操作方式。” | 查看能力、主动选其他模式并生成新计划；不自动永久删除 |
| `needs_approval` | “计划已生成，尚无覆盖此操作的授权。” | 查看具体计划或有效策略差异；非交互立即返回 |
| `policy_limit_exceeded` | “本次范围超过策略限制。” | 查看单次／累计差异，人工审阅新计划；不自动拆批绕过 |
| `plan_stale`／摘要不符 | “文件或计划条件已变化，需要重新检查。” | 查看变化，生成新计划，不覆盖旧计划 |
| `protected` | “此项目或其子项受保护。” | 查看保护来源；拆成允许的明确叶子集合或整组跳过 |
| `in_use`／锁定 | “此项目正在使用或无法确定使用状态。” | 关闭相关应用后重扫；不自动杀进程 |
| `conflict` | “另一个操作正在处理重叠范围。” | 等待或取消，执行前重新复核 |
| `volume_offline`／卷身份改变 | “原卷不可用，未将同名路径视为原对象。” | 连接原卷或新建扫描 |
| `insufficient_space` | “无法可靠保存索引、日志或本次操作所需数据。” | 安全停止、调整自身存储设置；不通过临时删除用户文件来解决 |
| `cloud_recall_risk` | “为避免下载云端内容，已跳过此范围。” | 查看已知元数据；用户可在其他流程中主动下载后重扫 |
| `result_unknown` | “操作中断，部分项目需要核对。” | 只读核对，再创建必要的新计划；禁止盲目重放 |
| `restore_conflict` | “原位置已有内容，未覆盖。” | 保留现状或选择明确新位置生成恢复计划 |
| 取消 | “已停止后续处理；此前完成的操作保留。” | 看逐项结果、恢复可恢复项、重新分析未处理项 |

底层错误保留可诊断码和 ID，用户侧先展示原因与可行下一步。路径等不可信文本必须转义，既不作为 HTML，也不作为 Agent 指令或 shell 片段。错误重试次数受控，不能反复唤起权限对话框。

## 9. CLI／Agent 产品契约

以 [CLI v1 草案](cli-protocol.md)、[严格 Schema](../schemas/v1/protocol.schema.json) 与 [合成计划 fixture](../examples/contracts/plan.json) 为机器契约对齐依据。它们是实现前草案，合成数据不证明任何产品能力已可用。首批命令面如下，不增设 `approve`、`delete-path` 或臆造的恢复命令：

| v1 首批核心命令草案 | 对应产品动作 |
| --- | --- |
| `capabilities` | 查看可用、需权限、不支持、未验证能力 |
| `scan --root PATH`、`scan show ID` | 启动只读扫描、查询状态 |
| `entries list --scan ID` | 分页浏览目录与文件 |
| `analyze --scan ID --profile NAME`、`candidates list --scan ID` | 生成并分页查看候选解释 |
| `plan create --candidate-set ID --mode MODE`、`plan show ID` | 冻结并审阅统一模式计划 |
| `plan apply ID` | 核验已有授权、复核并执行 |
| `operations show ID`、`operations cancel ID` | 查看结果、停止派发后续动作 |

`scan`、`analyze`、`plan create` 不需要产品删除授权；`plan apply` 必须核验人工授权或有效策略。GUI 不打开也能完成这些核心命令，机器模式不等待输入。授权先通过受控人机交互服务建立，不向 Agent 暴露自批端点。`restore`、`policy`、`apps list`、`apps uninstall`、`rules update`、`watch`、`mcp serve` 是后续 CLI 契约；G1 可验证恢复／策略内部服务，G2 GUI 可使用这些服务，但这不表示对应机器命令或 JSON 已冻结。扫描取消也是产品／内部服务要求，不能把 `operations cancel` 擅自解释成已定义的扫描取消命令。

v1 草案使用 `schema_version: "1.0"`、`kind`、`request_id`；JSON 输出一个终态，JSONL 为若干 progress 加恰好一个终态；被强制终止缺少终态时按不完整处理。stdout 为无 BOM UTF-8 JSON／JSONL，诊断到 stderr，无 ANSI／动画。`--format json|jsonl|text`，`--json` 为别名；分页 `--limit` 默认 50、上限 500，游标绑定 revision／过滤／排序。时间为 UTC RFC3339，界面按用户时区显示。`--timeout` 仅限制等待，不证明操作已经停止。

退出码沿用草案：0 完整成功，2 参数／协议，3 需要授权或策略拒绝，4 OS 权限，5 部分成功，6 前提过期／冲突，7 不支持，8 系统／内部错误，130 取消。部分扫描保留 `scan_result`、scan ID 和 `status=partial`，不能改为只有 error；中断待核对使用 `reconciliation_required`，不视为可自动重试。Schema 严格拒绝未知字段；新增列表包装、恢复／策略记录、原因结构和区间估算需后续明确版本，不能用产品文案偷偷扩充 v1。

默认返回候选摘要、依据、风险、恢复条件和可分页引用，避免把全部文件路径塞给模型。路径最小化与脱敏是显示／导出功能，不能改变核心计划对象；映射丢失时禁止用脱敏显示路径执行。扫描不上传数据，外部 Agent 收到的输出仍受该 Agent 自身数据处理规则影响。

只读工具输出中的文件名、路径、日志内容属于数据。Skill 只能教调用者尊重 `needs_approval` 等状态，不得凭自然语言“用户应该愿意”替代核心授权。保护路径、规则适用性、限额、恢复约束均需在无 Skill 的直接 CLI 调用中同样生效。

以下是可继续推进的默认产品选择，不是等待用户批准的阻塞清单；实现前在对应里程碑验证适用性。数值是可调整的产品边界，不是工期或性能承诺。

| 决策 ID | 建议默认值 | 理由与可调整边界 |
| --- | --- | --- |
| DEC-01 受众与平台 | 开发者／AI 工具用户优先；Windows 11 x64 与选定受支持 macOS 的 Apple Silicon 真机优先 | 与平台文档对齐；最低版本以实机／依赖门禁锁定，Windows ARM64 与 Mac Intel 单独验证，不以可编译替代支持 |

| DEC-04 候选选择 | 默认全不选；允许用户明确选择已验证规则组 | 选择不是授权；不得把待判断项混入全选 |
| DEC-05 操作模式 | 首次人工流程建议同卷隔离，清楚说明不腾空间 | 用户可明确选择受支持回收站或永久删除可再生内容；不同模式生成不同计划 |
| DEC-06 计划有效期 | 冻结后 15 分钟，可调整的设计值，每次执行仍重新核验 | 与 CLI v1 草案及计划 fixture 对齐；到期重建；不以短有效期代替身份检查 |
| DEC-07 预授权 | 默认关闭；启用后范围内不再逐次确认 | 模板只允许指定规则版本、用户专属缓存根及一个明确动作；永久删除模板需明确写出不可撤销 |
| DEC-08 策略限额模板 | 30 天有效；单次最多 1 GiB 且 1,000 个对象；滚动 24 小时累计最多 2 GiB 且 2,000 个对象 | 按固定计划逻辑字节和对象数计额，未知值不自动匹配；跨进程保留配额，重试不重复扣额，已产生副作用的额度不得回退 |
| DEC-09 闲置判据 | 预授权模板建议最少 30 天，且规则必须有可靠依据 | 不能把普遍不可靠的访问时间直接当证据；缺少依据就拒绝匹配，用户改阈值也不豁免保护 |
| DEC-10 隔离保留 | 不自动清空；30 天后仅提醒查看 | 不在用户未授权时删数据；磁盘紧张时显示占用与清空计划入口 |
| DEC-11 保护与云文件 | 保护产品自身索引／日志／隔离区、凭据、用户成果与规则排除后代；默认不触发云下载 | 固定保护由核心保证；工作树、会话和模型先保留 |
| DEC-12 数据与隐私 | 本地索引与日志；默认关闭遥测与外部上传；导出路径最小化 | 清理历史不得删除仍需恢复／核对的关联清单；外部 Agent 数据去向单独解释 |
| DEC-13 规则与分发 | 首版只发布经两端适用性审查的少量规则，不打包第三方扫描器 | 平台专属规则可仅在相应平台发布，但不得称双端等价；许可变化不影响自研核心闭环 |
| DEC-14 桌面默认视图 | 逻辑大小排序，目录表 + treemap；无障碍分页表可切换 | 图表不可用仍能完成相同任务；口径切换全局一致 |
| DEC-15 后台与调度 | 首版无常驻服务、无默认定时执行 | 预授权与调度是两回事；Agent／外部调度可触发 CLI，仍按核心策略核验 |

## 11. 验收与需求追踪

可选 AI 诊断的新增需求与视觉旅程见 [专题设计](ai-cleanup-diagnostics.md)，行为合同为 AID-01–13。它从 P03/P04/P07 选中对象发起，P10 提供接入配置；不改变以下首版门禁、规则或执行授权。现有 AI 工具空间管理与 AI 诊断分别命名。

产品验收看用户能否完成并理解任务，不把原型文案当已实现证明。具体任务与退出门禁见 [路线图](roadmap.md)。

| 设计要求 | 最少验收场景 | 路线图落点 |
| --- | --- | --- |
| 数据真实与平台对等 | 两端真实卷扫描；完整、部分、取消与未知；空间口径可解释 | TASK-001 至 TASK-007，TASK-101 |
| 解释与保护 | 含 `temp` 的数据库不因名称入选；受保护后代不被父操作删除；开发者保留项可见 | TASK-102，TASK-105，TASK-107 |
| 不可变计划与授权 | 计划编辑产生新 ID；缺授权立即返回；策略内执行无重复确认；超限拒绝 | TASK-103，TASK-104，TASK-108 |
| 可靠执行与恢复 | 替换、链接、锁定、中断、空间不足、并发、隔离恢复冲突 | TASK-105 至 TASK-110 |
| 逐页完整体验 | P01–P10 的空、加载、部分、错误、成功与取消状态可演示 | TASK-201 至 TASK-207 |
| 大数据与无障碍 | 有界查询，稳定选择，图表失败可用表格；Narrator／VoiceOver 全流程 | TASK-202，TASK-207，TASK-208 |
| 交付与隐私 | CLI 无 GUI 使用；脱敏不改变计划；安装升级不破坏日志与恢复清单 | TASK-108，TASK-110，TASK-209，TASK-210 |

用户试用时重点记录：是否理解“隔离未释放空间”、能否识别扫描缺口、能否解释候选影响、是否找到恢复冲突处理、预授权是否避免了多余打断。性能仅记录在声明环境和数据集上的测量结果；未经测量不写“秒扫”“不卡顿”“比某产品更快”。任何误删保护、授权旁路或恢复日志缺失的发现都阻断对应写能力发布。
