## 关键取舍

Rust 是适合本项目核心的选择，但速度主要取决于系统枚举机制、元数据补查次数、I/O 模式、索引结构与缓存条件。不能因语言选择就承诺超过 WizTree；同样，Tauri 的小包体也不能代替实际安装包和内存测量。

Mole 的值得借鉴之处是维护入口与反馈方式；WizTree 的重点是快速定位空间去向；disk-cleaner 的重点是 Agent 工作流。新的共同基础是统一的扫描观察值、规则、固定计划与执行记录。具体参考证据见 [REA 调查](research/rea-investigation.md)。

平台 API 对“正在变化的文件名”有真实限制。尤其 POSIX 的检查后 unlink/rename 不具备通用的“仅当 inode 仍等于 X”原子条件。产品应按已验证的后端能力开放动作；在严格身份要求下无法保证的操作返回 unsupported，而不是以“用了 Rust”解释为已安全。详见 [macOS 名称竞态分析](platforms/macos.md)。
