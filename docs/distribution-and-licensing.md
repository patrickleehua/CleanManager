## 依赖选择与维护

拟选组件包括 Rust 标准库与平台 bindings、CLI 参数/序列化、SQLite、Tauri/TypeScript；具体 crate/npm 版本在原型阶段锁定。每个直接与传递依赖记录版本、来源、许可和用途；生成 SBOM、第三方 notices 与构建清单。区分源码包、构建工具、运行时组件和可选外部程序。

FFI、二进制解析、特权 helper、更新器是独立审查边界。解析器按真实输入长度、版本、对齐与边界校验，不能将盘上结构直接无校验 cast 为 Rust 结构体。依赖升级保留性能/正确性基线，更新锁文件后重新执行受影响的验收。

## 发布通道

Windows GUI 目标安装包、独立 CLI 归档分别验证平台签名和安装路径；Windows x64、ARM64 为不同发布组合。不要全局修改用户 PATH 或覆盖已存在的 cleanmanager 命令而不提供明确安装选择。具体 API 与签名步骤见 [Windows 发布设计](platforms/windows.md)。

macOS 优先站外 Developer ID 分发，签名覆盖 GUI、独立 CLI 与嵌套 helper；分别验证公证、正常下载 quarantine 和 Gatekeeper。Apple Silicon 与 Intel 的测试不能互相代替。需要用户自己在系统设置授予的权限，应展示限制与下一步，不修改 TCC 数据库。[macOS 发布设计](platforms/macos.md)。

GUI 与 CLI 共用核心版本信息但可独立运行；只装 CLI 不要求运行窗口。首版不默认安装常驻系统服务。更新时检测协议/数据库/规则兼容性，不能更新 GUI 后继续让不匹配的 helper 接受写命令。

## 更新链与故障恢复

1. 更新元数据与产物均验证签名、版本、目标平台/架构和完整性。TLS 不能替代发布签名；平台代码签名和更新签名分别检查。
2. 更新前停止接收新写计划，等待安全边界，保存进行中操作的日志。不能杀进程后按“全部未执行”重新开始。
3. 数据库迁移先检查版本并保留可恢复材料。可再生扫描索引允许重建；操作历史、隔离清单和待核对 intent 不能随索引一起丢弃。
4. 规则更新验证来源、版本、摘要和测试证据；新版本不得扩大已授权计划。紧急保护更新可以收紧可执行范围，并清楚说明失效原因。
5. 回退程序版本之前检查存储兼容。回退不能恢复已删除数据，也不能自动重放旧动作。升级/回退失败保持诊断与恢复入口。

[Tauri 更新器](https://v2.tauri.app/plugin/updater/)提供更新签名机制；上述计划、规则、日志与 helper 兼容检查仍属于本项目责任。CLI 的签名自更新、存储迁移与自卸载机制已实现，但目前没有签名的发行包，也没有发布密钥（MVP 任务 14.2 未完成），见 [安装、更新与卸载](install.md)；发行隐私说明见 [隐私说明](privacy.md)，第三方声明由锁文件生成于 [第三方声明](third-party-notices.md)。

## 本地数据与诊断

磁盘文件名、应用清单、目录大小可能暴露个人或业务信息。默认所有扫描索引、规则分析和操作记录保留本机；无默认遥测、无默认上传整个目录树。Agent CLI 只提供必要摘要和分页字段；Agent 后续怎样处理数据取决于其运行环境，不能承诺所有外部模型都本地执行。

日志默认记录任务 ID、类型化状态与必要的对象定位，不记录文件内容、令牌、环境变量或凭据。诊断导出先展示范围并脱敏显示路径；涉及恢复所需的原始身份不能用脱敏数据替换内部真值。日志容量、保留与用户主动清除能力需在产品设置中明确，待核对操作不能被普通轮转清掉。

本轮 REA 原始证据可能包含本机研究路径与工具诊断。它们为本地工程证据，不作为遥测自动上传；若向外分享研究包，应先审阅路径信息并保留可核验哈希，避免改写原始证据后仍宣称是同一份 bundle。

发布门禁与实际验证要求见 [验证计划](verification-plan.md) 和 [路线图](roadmap.md)。
