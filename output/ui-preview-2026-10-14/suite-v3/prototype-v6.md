更新：2026-10-15。对应 `add-mole-parity-suite` 任务 16.6。入口：[index-v6.html](index-v6.html)（本地预览可用 `python -m http.server` 在 `output/ui-preview-2026-10-14` 下启动，打开 `/suite-v3/index-v6.html`）。

v6 叠加在既有原型之上：`app.js`、`style.css`、`features-v4.*`、`ai-diagnostics-v5.*` 与 v5 的 `index.html` 均未改动；新增 `index-v6.html`、`suite-v6.js`、`suite-v6.css` 依次加载，覆盖导航、页面映射与少量旧函数（标题、计划、托盘、磁盘右键与详情）。[v5 说明](prototype-v5.md) 保留为上一轮快照。

## 本轮变化

- **按 D14 重排信息架构。** 顶栏是五个工具：清理、软件、优化、分析、状态（Alt+1–5）。左栏是扩展入口：计划、活动、恢复、Agent、AI 诊断、设置（Alt+6–9、Alt+0、Alt+,），图标下带名称。每个工具顶部有子工具条：清理 = 清理目录 / AI 工具数据 / 构建产物 / 安装包；软件 = 应用清单 / 卸载 / 更新 / 启动项；优化 = 维护任务 / 性能诊断；分析 = 磁盘分析 / 空间洞察 / 回收站；状态 = 系统状态 / 常驻工具。原“总览”并入 分析 › 空间洞察（P02 的洞察卡片），`#home` 和 `#maintenance` 旧链接会自动跳转。
- **“扩展概念”标记改为规格与门禁状态。** 每个子工具和页面标题下都显示状态词（已规格 / 实验 / 不可用）、G1–G4 门禁刻度和 Requirement ID，点击“状态说明”可以看到定义。状态按 tasks.md（2026-10-15）推导：有实现子任务勾选但门禁证据未齐的记为“实验”；只有规格的记为“已规格”；当前平台不提供的记为“不可用”。全部 21 个页面在两种主题、三种宽度下都不再出现“扩展概念”。
- **平台预览。** 右上 Win/Mac 切换不改变入口名称与顺序，只切换平台惯用语（回收站/废纸篓、资源管理器/访达）和适用性；只在 macOS 提供的能力在 Windows 上原位标为“不可用”并说明原因，不隐藏。
- **新增演示：** 卸载两段计划、维护任务、系统状态、常驻工具、手选回收站，以及空间洞察。构建产物、安装包、更新、启动项和性能诊断也有简版页面，五个工具因此都完整。
- **视觉统一。** 令牌与 `apps/desktop/src/styles.css` 对齐：muted、warn、danger 使用桌面端校正后的深色值，增加 line-strong 和 seal-bg，品牌标记与桌面端一致。计划陈述条、摘要封印（DELETE + 摘要）、形状编码的结果标记（圆 / 环 / 菱形 / 短横 / 三角 / 方块）沿用桌面端 P05/P06 的组件语言。没有使用对标产品的星球、动物、名称或文案（GUI-11）。

## 演示路径

1. **卸载两段计划：** 软件 › 卸载 › Cursor。第一段计划包括退出应用和运行注册的卸载程序，显示“预计残留约 3.4 GiB（估计，不预授权）”。可以勾选“应用在时限内未退出”，然后选择取消（不执行任何删除）或强制结束（需要二次确认）。重扫后结果为部分完成，因为安装目录仍有剩余。之后进入第二段，残留单独审阅，共六组。只有缓存与日志默认选中。模型、凭据数据库和设置默认不选。workspaceStorage 被 Cursor Nightly 共用，标为 shared_owner 并保留。归属不足的目录标为 owner_unknown。注册表项标注“先备份”。勾选“备份位置不可写”后，只有注册表项会被跳过。完成页使用统一结果摘要，收尾步骤逐项报告（helper 注销失败，所以是部分完成），并提供“恢复注册表项”入口：已被重新创建的键会跳过，不覆盖。另有几个对照：Git 走 winget 适配；Codex CLI 的会话默认不选，脏 worktree 为 blocked；便携版来源未知，只提供能力说明；终端防护不可卸载；“孤立残留”全部为仅审阅。运行中切换应用时，旧序号的结果会被丢弃。
2. **维护：** 优化 › 维护任务。每项任务都写明它解决的问题、影响、适用性和耗时，并可以加入保护。“开始维护”只集中请求一次管理员授权，对话框里列出需要授权的两项。允许后，六种结果各出现一次；拒绝后，这两项记为 skipped（未授权），其余任务继续。只要有 failed 或 attention，就不显示“全部完成”。搜索“注册表优化”只会看到不提供此类操作的说明。
3. **状态：** 状态 › 系统状态。九个指标卡分别声明 可用 / 不可用 / 需要权限；温度和风扇显示“未知”，不写成 0。健康分为 74，权重条按公开权重 30/25/20/15/10 分段，温度不计入并重新归一。诊断行链接到未签名、用途未识别的进程。进程列表显示签名和发布者，可以排序和置顶；关键进程、安全软件和本工具自身不可结束。另附持续高占用提醒（需要常驻组件）和 CLI JSONL 示例。
4. **常驻工具：** 状态 › 常驻工具。托盘组件默认关闭，开启后显示面板预览、登录项和采样状态。保持亮屏可以设置时长并倒计时，结束后恢复设置。清洁屏幕会屏蔽按键，按住 Esc 2 秒或等 30 秒后退出。隐私提示和设备电量提醒只在本地显示。风扇、充电上限、网络低延迟和 Touch ID 在 Windows 上为“不可用”；切到 Mac 预览后显示“需要 helper / 机型未验证”。设置中新增“常驻组件与 helper”生命周期页。
5. **手选回收站：** 分析 › 磁盘分析 › Downloads，右键“素材视频.mov”会出现“移到回收站…”、显示位置和复制路径。Downloads 本身因含受保护后代而被拒绝，用户目录根属于硬拒绝。计划对话说明三点：只允许移到回收站、不匹配预授权策略、移动前后都核验身份。选中“安装包”目录时会出现占用失败（Setup.exe，PID 7720），可以重试，但不会自动结束占用进程。在 分析 › 回收站 可以放回对象，或另建永久删除计划；输入 DELETE 和摘要前 4 位后，执行按钮才可用。“卷不支持回收站时”演示计划创建失败，并且不提供直接删除。
6. **空间洞察：** 分析 › 空间洞察。每张卡显示已知大小，或显示“未知 / 数量 · 大小不可得”，并附观测时间；点击打开只读说明，不提供移到回收站。“旧下载”按大小排序，没有预选项，进入处理时走手选回收站流程。
